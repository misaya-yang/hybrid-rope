# Hybrid-RoPE experiments

Use the [research index](../../../docs/research/next_stage_20260912/index.md)
for priorities and [experiment index](../../../experiments/index.md) to select
the relevant result owner and implementation. Read the
[experiment workflow](../../../docs/research/protocols/EXPERIMENT_WORKFLOW.md)
when preparing or executing work. Do not load every historical plan.

Complete the user's authorized question with the least costly comparison that
distinguishes the relevant explanations. Reuse completed baselines with the
same contract. A public-parameter rule is fixed before model outcomes; do not
fit its parameters from checkpoint states or evaluation labels.

Preserve checkpoint, table/reference grid, gain, input identity, length,
precision, decoder, scoring and aggregation. A complete public deployment
comparison and a controlled shape comparison answer different questions.
Define completion by complete required arms and the paired report, not GPU
utilization, an exit code, or the presence of a launcher.

Observe current processes before touching an authorized remote execution.
Do not stop unrelated jobs, replay old queue wrappers, redownload validated
assets or rebuild unchanged preparation just because the machine changed.
Keep CPU reports distinct from model execution and partial results distinct
from completed comparisons. New paid runs require current authorization.

Finish the owner report, retain conditional gains/failures, and use
[evidence registration](../hybrid-rope-evidence/SKILL.md) when a result is adopted
by the manuscript. Keep raw streams and checkpoints at their recorded owners;
portable compact reports and code travel through Git.
