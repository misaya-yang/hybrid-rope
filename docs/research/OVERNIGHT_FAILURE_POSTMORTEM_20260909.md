# 2026-09-09：研究失败复盘与工作方式调整

本次唯一任务是复盘，不恢复研究。已通过 port27741 SSH 读取无卡服务器的既有输出、运行回执和日志；没有加载模型、运行新实验或下载模型。对应机器可读核验在 `OVERNIGHT_FAILURE_AUDIT_20260909.json`。本文件是项目内复盘，不改写通用 AGENTS.md，也不创建新的实验队列。

## 结论

研究目标难且结果不确定，但任务难不能解释全部失败。主要可控问题是：执行端能够持续生成候选、实现和局部解释，却没有让这些工作持续收敛到一个重要、区别于已有方法、可由完整模型结果支持的核心判断。用户承担了过多纠偏工作。

不能承诺下一晚一定发现可发表方法，也不能承诺消除实验负结果。应承担的责任是减少无信息的重复、准确区分可交付工作与未知科研突破、让每次失败实际改变后续决策。无需把研究目标降低成简单命题；需要改变执行单元和决策方式。

## 最关键的偏离：实验没有回答原计划的问题

原计划 `experiments/native_sparse_position/DESIGN_SOURCE.md` 第4.7A节已经要求：在同一批Q/K的**错误候选对**上计算位置变化与摘要误差，找出排名翻转，再检验对应错误是否影响完整答案。它也已写明同数量对照、强selector和最终生成要求。因此主要问题不是缺少一份正确计划。

实际 `activation_audit.py::audit` 虽计算了精确分数、均值分数与选中集合，但保存的主指标是全体合格查询/块的平均保留率、平均value误差和平均logmass误差。首轮只覆盖两个前缀、三个层、八个末端query。它没有完成原计划要求的错误候选对条件归因。`CORE_DIAGNOSIS.md` 开头也明确承认这一缺口，并注明用户纠正后停止自动模型/归一化队列。

这类初步诊断本身可以做。错误发生在决策连接处：尚未回答“特定错误是否由位置相关摘要造成”，就继续扩展相邻诊断和接入方向，原问题仍悬空。应当从相同失败中补足能够分开竞争解释的关键证据，或者明确说明为何这种测量不能识别该问题，而不是把总体均值无优势当作路线已被检验。

后来的source修复与精确oracle确实建立了更具体的答案恢复；但Post/Pre聚类均有效且相近，又把解释指向了完整内容摘要，而没有留下位置设计的特有收益。此时该实验完成的是机制诊断。它不能作为新的位置方法已经形成的依据，也不能把“接着再想一个摘要”当成自然晋级。

## 根因与促成因素

1. **把开放式科研目标直接当成自动执行的完成条件。** “持续直到solid结果和论文”不能保证收敛。如果每次局部失败都产生一个新候选而不关闭原判断，持续执行会变成持续消耗。长期目标应保留，但一次执行需要解决明确判断；明确判断也不能被用作提前宣布长期目标完成的代理。
2. **混淆诊断价值与方法价值。** 精确oracle能修复，只证明在其干预范围内存在可恢复信息，不保证低成本可学习/可部署近似能修复。旋转不变、logit边界或平均恒等式不是完整生成收益。诊断若没有结果到方法选择的映射，很容易无限下钻。
3. **混淆归因对照与实用基线。** 固定64-token页有助于隔离摘要变量，但实际同token预算可以用更细Quest页。二者都合理，却回答不同问题。上一轮最后补强基线是正确纠偏；需要避免先围绕弱基线积累方法期待。
4. **负结果没有充分收束路线。** PSR局部弱信号后，记录中出现自然QA、另一个模型、共享头归一化和MiniCPM接入。某些转换有机制理由，也有用户明确改变目标的阶段，不能把所有换题都归咎于执行端。但每个新接入都承担下载、环境和解释成本，必须说明它能区分什么，以及为何现有资产不能回答；“这个模型更现代”本身不够。
5. **测量口径成熟得晚。** 开发任务的答案格式、header和raw/trimmed命名混在一起，导致需要重新解释甚至回放。应保留完整生成与EOS证据，同时让主指标匹配实际研究主张；研究检索内容时，格式遵从可以另报，不应让纯格式差异替代能力判断。既已冻结的主指标不能看到结果后改写。
6. **研究材料没有始终被当成待检验假说。** Pro材料、漂亮代数和理论术语会产生方向已成立的错觉。RefCarry的平均logit与概率边缘读取差别就是具体例子。执行端应在扩展实现前检查最影响主张的假设，但不能反过来要求完整理论才允许一个有信息价值的实验。
7. **状态记录过多，决策摘要不足。** HANDOFF有多层覆盖说明和历史PID，证据保存充分，但“当前否定了什么、留下什么、为何下一步值得做”不够突出。代码量、测试数、报告数和GPU忙碌不能替代这一摘要。

这些是从结果与记录推断的工作方式问题，不是对未恢复的全部对话或每分钟活动的精确因果归责。

## 应保留与不应重复的工作

应保留：BM在OLMo的局部正结果及Qwen迁移限制；source/wrong-page与exact oracle的因果证据；最终强基线；冻结输入、源码快照和完整输出。跨模型负结果、强基线击败候选都是有效信息，不应因没有论文便全部称为白做。

应避免：没有新条件或新可证伪预测就重试同一失败家族；用增摘要数解释成位置创新；在代理指标变好后直接扩模型；明知属于已有方法仍靠换名称维持论文期待；在核心结果尚未成立时把论文重写当作进展证明。

单个小样本负结果只限制其被检验条件。重开路线允许，但应指出什么新证据/机制改变了原判断，而非无限封杀或换名字重跑。

## 建议的工作方式

**改变实际决策，不再增加一套提示词规则。** 现有计划和AGENTS.md已经要求保留目标、合理实验和自主纠偏；规则数量不是瓶颈。以后是否改善，要看实际行动是否仍在回答同一个重要问题，而不是看我能否复述这些原则。

保留大的研究问题。由助手先读历史并自主把它转为当前最关键的一个判断，用户不必负责拆分每个实验。下一次执行开头用一小段说明：已有事实、最关键未知、所选对照、不同结果将怎样改变决定。无需新增例行审批或固定小时门槛。

机制研究先确认可复现失败、干预的解释范围与竞争解释；方法研究尽早同时面对相关强基线和去掉所声称新设计的对照。复用可比结果；样本量由需要分辨的效果和成本决定，不能以超小冒烟代替可靠判断，也不能默认全模型全任务矩阵。

结果出来后立即归入三类：支持某个具体主张、否定某个具体条件下的主张、当前测量不可判定。写出这一次结果如何改变下一步。不可判定要说明缺的是何种测量，不得默认“换模型再看”。负结果之后允许继续独立思考；没有新依据时不自动消耗付费算力，也不把暂停计算说成放弃目标。

汇报以“核心判断改变了什么、还缺什么”为中心。实验失败可以是该次判断的完成，绝不是整个论文目标完成。论文主线重构应跟随已站住的结果；必要的研究草稿可以写，但必须与结果稿区分。

每轮结束维护一个简短决策段落和既有证据链接，不再追加一套繁重流程。若当前无法提出值得计算的判断，助手要明确承认并说明卡在哪个假设，继续授权内的低成本证据工作；不能用一串新名词掩盖没有办法。

具体到已发生的错误，新的行动应当是：

| 再次出现的情况 | 应执行的动作 | 不能据此作出的决定 |
|---|---|---|
| 总体平均指标差异小，核心假说是条件性失败 | 回到实际失败对，检查目标变化、估计误差与最终答案的连接 | 宣告原假说普遍失败，自动换模型 |
| 一个oracle恢复答案 | 判断它注入或访问了什么额外信息，以及该信息能否由合法方法得到 | 把oracle恢复直接写成部署方法前景 |
| 候选明显胜过Mean，但去掉位置设计仍相近 | 将收益归到已有证据支持的因素，直接面对相关强基线 | 继续维持位置创新叙事 |
| 用户在任务中质疑判断或询问状态 | 回答后继续当前授权任务，并把纠正落实到行动 | 用道歉或能力声明结束尚未完成的任务 |
| 没有找到可靠的下一步 | 说明具体哪个判断卡住，继续有目的地检验竞争解释；若无有意义动作则如实交代局限 | 随手发明新方法名、换题或假装持续工作必然得到突破 |

本次对话中，助手先把研究复盘转去核算成本，又在回应批评后结束任务，这两次行为直接复现了同一问题：容易完成的局部响应替代了用户持续要求的目标。它们属于本次复盘的失败证据，不能只归为表达不够好。

## 对任务难度的诚实回答

用户要求的“独立找到重要新问题、设计方法、得到强结果、完成论文”是高不确定性的科研组合任务。我可以承担可核验的推导、实现、反例、实验与复盘，但当前证据不支持把我当成能在一晚内稳定交付独立科研突破的系统。降低命题难度不能解决判断与执行失配；加强提示中的“必须成功、不能停”也不能创造突破。

可以承诺并核验的是工作质量和证据纪律，而非正结果或录用。推荐改变协作中的交付单位，保留研究难度：用自主完成的重要判断逐步逼近论文，而非把持续产出活动误认为必然逼近成果。上述方式旨在减少死循环，不保证以后不出现失败。
