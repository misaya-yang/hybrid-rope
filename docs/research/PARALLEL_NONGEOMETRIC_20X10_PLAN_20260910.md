## 3. 新综合：二力框架（arc restoration vs phase separation）

四个独立数据点落入同一个二维结构：

- **arc 力**（窗内收益）：把测试相位跨度压回已学范围 → 窗内/短端表现升。证据：`E1_s29_more`（加压缩→32K +8.33pp）；`E3 gain074`（降 logit 温度→32K 100%）；BM 在 OLMo 32K +4.44pp。
- **separation 力**（长端绑定）：相位分离度决定相似键在长距离的判别 → 压缩降低分离度 → 误绑定。证据：BM@Qwen 128K MK2 75→50（9289114 误绑定反例）；`E2_tail_more`（慢尾加压缩→同值重复填两键）；GapCapped（radix gap→歧义距离）；`E1_s28_less`（减压缩=增分离→128K +5.21pp，2胜0负）。

**推论**：静态单表被迫在两个力之间做全局妥协；MrPro 是妥协点的一个局部最优近似。三条出路，各对应我的实验：
1. **槽级重新谈判**（哪些槽付 arc、哪些槽保 separation）→ 实验 4（双侧门控）、实验 5（分离度优先设计）、实验 1（全局形状×预算析因）。
2. **按长度解耦**（窗内用 arc 配置、长端用 separation 配置）→ 实验 6（row-wise 动态，窗内≡Native）、实验 2（S=2@64K 尺度匹配）。
3. **确认妥协点是否已饱和** → 实验 8（搜索探针）。

该框架的可检验预测（预注册）：**任何降低中带/慢带分离度的改动，其 128K 失败模式应以误绑定为主；任何提高 arc 保真的改动，其收益应集中在 ≤64K。** codex 后续结果（E9/E10、s28/s29 新 seed）可直接检验。

## 5. 10 个实验（v2 重排）

公共协议：复用归档 MrPro 基线（`summarize_candidate_screen.py --baseline results/bm_transfer_20260908/run_qwen3_01/MrPro.jsonl`）；NLL 4 文档首筛 → 12 行 → 36 行 → 50 行 MK 面板 → 扩大。阈值：窗内 ΔNLL≤+0.03、OOD ΔNLL≤+0.05、MK2 12 行内 −1 题 / 50 行内 −5pp 不淘汰、任意两任务同时掉 ≥2 题即停。表安装走 `cross_audit/tables.py::install_static`（64 槽原顺序、SHA 身份）。

### 实验 3′（#1）｜MK2/MK3 50 行高功效判别面板 — 执行成功率 ~90%，~2h
- **构造**：`scale_transport/ruler_full_prepare.py` 产 MK2/MK3@128K 各 50 行（冻结 seed）；跑 MrPro（补 MK3 本地基线缺失值）+ Native + BM + **codex 的 s28_less / s29_more / gain074 三张已胜出候选表**（对方数据直接复用，不重跑其构造）。
- **v2 更新原因**：codex 两个正候选的验证需求使这成为双方共同瓶颈；E3 首轮假阳性（1胜0负→36 行反转）实证了低分辨率面板的双向风险。
- **失败价值**：MK3 全员≈0 → 多键绑定@128K 是冻结模型天花板，"赢 MrPro"主张转向 64K/MK2 精度，双方全局策略改写；s28/s29 在 50 行上蒸发 → E1 信号是 36 行过拟合，任务反馈选择器降级。
- **成功深化**：所有后续候选挂此面板；MrPro/BM/s28 的 50 行 MK 差成为论文表格。
- **排除（5）**：单 passkey 扩样（饱和 100% 无信息）、13 任务全量基线（4.4h/臂）、人造绑定任务（生态效度）、50 行 VT/FWE（非判别项）、只 MK2 不补 MK3（MK3 才是缺失值）。

### 实验 5′（#2）｜分离度优先表 + 5 点预注册回测门 — ~30%（门通过才跑 GPU），CPU 半天 + 15min
- **构造**：目标 = min over Δ∈{1K,2K,4K,8K,16K}、位置 p≈90–128K 的槽间相位分离度；约束 = ①相邻周期比≤阈值（无 radix gap）②128K 相位跨度≤learned arc×安全系数 ③外频段逐位不变。**回测门（v2 扩为 5 点）**：指标必须在已有数据上排序 MrPro>BM、MrPro>GapCapped、MrPro>E2_tail_more@128K、s28_less≥MrPro@128K、并解释 s29_more 的 32K 收益（arc 侧）——任一失败则不花 GPU，交付否证。
- **v2 更新原因**：E2_tail_more 的误绑定失败是分离度受限假说的**前瞻性**确认（设计时预测"降分离→误绑定"，它发生了）；s28_less（增分离→128K 赢）是同方向的第二个点。二力框架（§3）给这张表一个明确故事：在 arc 约束允许的全部空间里最大化 separation。
- **失败价值**：门失败 → 静态判别性代理连任务机制形式都不成立，"从几何设计表"整体关闭；门过 GPU 输 → 可回测不可预测 = 仓库中心主题最干净实例，论文素材。
- **成功深化**：MK2 75→87+ → binding-first 设计原则 → 实验 3′ 面板确认 → 跨模型（构造规则 checkpoint 无关，运输性最好）→ 论文任务机制化分配理论主线。
- **排除（6）**：格点钉扎（静态唯一性冻结判决，只做 post-hoc 诊断）、pair-volume/min-eigenvalue（训练线尸体，长度反转）、phase-isotropy（尸体）、最大熵/Haar（16K=0 尸体）、覆盖度代理（C4 尸体）、无门直接 GPU（代理谬误重犯）。

### 实验 4′（#3）｜双侧敏感度门控 + G_attn 交叉验证 — ~30%，~1.5h
- **构造**：8组×8槽分组有限差分测窗内 ΔNLL（32K，16 文档）→ 细化边界槽。双侧规则：**压缩** {arc 溢出大 ∩ 实测代价小}；**解压**（相对 MrPro 回退向 native）{代价大 ∩ 溢出小}。梯度敏感度（shared_frequency_response.py 的 J/G 对象）只交叉验证不进构造。**汇聚效度检验（v2 新增）**：门控坐标是否独立提名槽 28（解压侧）/槽 29（压缩侧）——若与 codex 的任务反馈提名重合，两种选择器互为验证；若不重合而两张表都赢，说明存在多条通往同一收益的路径；若我的提名表输而 codex 的赢，测量驱动选择器降级、任务反馈升级。
- **v2 更新原因**：E1 证明单槽效应真实可寻且方向双侧；E7 的 160× 定量失配给 C9 臂一个具体可检验预期。
