## 已有机制证据及限制

1. 在保存的真实 Q 上，原 PM 的 proxy 相对 C 全部占优，而采用同一 raw V 权重的真实 prefix mass 在九条中七条反向。去掉未来新 token 分母权重后，仍是同样七条反向。因此，分母中的 prefix mass 权重并不足以单独解释错位。九条包含共享家族，且其中六条 Full 记录答案本身错误，不能把接近它们的局部 attention 当成任务正确上界。
2. KVzip 实际保留集合重新核对了原前缀 tokenization 及每行 keep hash。自然背景16记录的 000/001，目标 value token 平均保留率约 **30.6% / 33.7%**；只有 **2/72、3/72** 个层/head 单元保留完整 value。256记录中，即将用于诊断的002/003只有约 **11.1% / 20.2%**，两条都没有层/head 单元保留完整 value。这仍是原文保留证据；其他隐藏状态可能包含相关信息，不能直接推断因果。
3. 单 key 的 Frobenius 准则确实优化了它声明的二阶矩目标，但并不适用于任意查询分布。实际候选代码的64-token有限反例中，整体遗漏协方差平方范数降约39%，一个查询方向的二阶平方误差反而升约74%，且造成真实 logmass 排名反转。一般查询的平方二阶风险需要原始四阶矩；只用均值、协方差不足以在非 Gaussian 情况下确定它。
4. 查询二阶矩子空间、低秩因子、FP4 和 Gram 构造已经在 [COBS §5.4–5.6](https://arxiv.org/html/2607.09052v1) 中出现。当前 NOSA 上的 full-space rank2 适配不是作者完整强方法；查询加权或 Gram 计算本身不能作为新颖性结论。

## PC2：已补采真实选块边界，执行候选内完整二阶重算

`pc2_cutoff_capture_dev_v1` 重放既有multiquery000与single000的完整协方差自由生成，两条raw token均逐项精确复现旧输出。只读观察最后prompt与首个实际摄入答案query，保存112个层/query状态、224个KV组状态的逐head块分数、最终集合、实际live集合，以及末prompt中full/rank1分歧块的原始K/CIS。所有224组单query重算full集合与live集合相同。状态文件约20MB并已同步；197.857秒运行包含重算COBS/rank1等观察开销，不用它作方法时延。

已有汇总不足以分析实际名额，因此这次读取具体排名：使用原reader topk=64作为粗排候选宽度、保持原自由QK名额（此处15），普通PC2候选对full自由名额的平均覆盖约96.55%，但最差仅46.67%。在候选内重算full二阶分数、保留候选外近似mass用于GQA分母，并在归一化后将QK提名限制在候选内，full自由名额匹配率由79.20%提高到95.74%。这是两个既有输入上的状态级模拟，224组不是224个独立样本，不能代替生成。最差状态说明这不是认证exact算法。

模拟也暴露了必须处理的细节：如果候选内换成更准确分数后，仍允许候选外未校正的高估分数直接参与提名，个别状态的exact自由名额匹配可降到0。当前实现明确限制候选资格，同时在GQA每head的分母中保留候选外估计；没有把不同head的未归一化mass直接相加。

新增 `candidate_refinement.py` 用普通PC2粗排以避免SVD，再只对64候选块读取raw K计算完整CIS加权均值/方差；当前块仍用精确因果mass。最终原CIS填充、总预算64块、位置、reader和模型权重均不变。CPU测试通过候选分数与全量full参考一致、候选覆盖全部时恒等、未来token扰动不泄漏及原名额输出。候选宽度沿用已有topk，未按DEV答案调新阈值。

`pc2_refine_full_two_dev_v1` 两条已完成：multiquery000官方答案项召回3/4且EOS（旧rank1为0/4、COBS参考1/4、full为4/4），single000保持1且EOS。这里沿用RULER官方答案项召回，不能称完整答案字符串正确。prefill约27.05/25.46秒，旧full记录约21.27/20.33秒（含少量旧observer开销），当前没有wall-time收益。refinement raw点积数约为相同活跃阶段dense参考的39.96%/41.24%，但不含全部coarse评分/summary/gather/reader成本；累计物化的FP32 gathered-K元素体积约1.43/1.36TB，这是张量规模计数而非硬件流量实测，可能解释当前额外开销。

正在完成四任务各前四条的既有16DEV面板 `pc2_refine_full_dev_v1`，先看整体质量是否值得内核优化。原打算复用两条，但共享复用函数的候选白名单不含新selector，静默导入0条，因此本轮实际新增16次、其中2次重复；重复不算独立证据。该接口问题已在独立准备目录修复：沿用原模型/数据/精度/reader/预算校验，再比较保存源码中两个实际计算定义的AST；仅wrapper变动可复用，计算改变拒绝。CPU已验证两条旧结果能被导入，改二阶系数会被识别；未修改运行中快照。

相关工作边界：[HISA](https://arxiv.org/html/2603.28458v1) 已有粗块过滤后在候选内精排的结构；[COBS](https://arxiv.org/html/2607.09052v1) 已有协方差压缩、query子空间及FP4；[uncertainty-gated selection](https://arxiv.org/html/2607.07724v1) 通过小cutoff间隔扩展最终读取预算。当前仅是固定最终预算的PC2修复候选，不能把粗排/精算本身称为新颖贡献，也不与上述论文不同模型/任务/预算下的总分直接比较。

## 完整二阶的原生BF16投影/FP32输出：算子已通过，配对生成中
