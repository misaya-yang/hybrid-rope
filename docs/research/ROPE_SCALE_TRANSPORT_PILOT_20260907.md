## 输出与停止

- CPU 阶段先完成模型下载、文档和评测行冻结、三个数学测试及必要运行检查；无卡时不加载完整模型到 CPU。

- GPU 路径限定 BF16 Flash SDPA。第一个实际采集前向同时检查自算 attention replay 与模型输出，相对范数误差大于 0.05 就停止查实现。这是 BF16 工程容差，不是能力门槛。
- OOM、非 Flash、数组/输入身份漂移、非有限数值或硬超时立即停当前试验。硬超时允许 15 秒退出清理，主作业超时设置不超过总上限减清理余量。
- λ=0 输出 REFERENCE_ONLY：本轮未得到新表，不对相同 Mr 数组重复生成，不宣布新方法有效或方法类失败。
- λ>0 才测本方生成。若 Native 明显退化或长任务无可用输出，结束本轮，分析已存输出，不追加训练/扫参。

四个工作机 CPU 测试通过（最终回读 13.63 秒）：直接旋转+causal GQA 对照、分位尺度恢复与可见窗口反例、有界投影与独立小型优化器对照、真实小型 Qwen attention hook/输出布局与最后 logits 接口对照。准备阶段发现 Transformers 返回 BatchEncoding，已显式使用 return_dict=False，冻结行数为 8 Native/8 long、实际输入 8399–60445 tokens。CLI 检查通过。正式大模型 hook 和最终任务改善未验证；它们由受预算限制的本轮运行给出，不在本文件提前写成成功。

## 首轮构造回读与预算内的能力诊断

构造运行已返回 REFERENCE_ONLY（146.44 秒）：λ=0 的 DN=22.44445、背景 log-mean-exp=5.38381；原始 λ=1 提案的 DN=23.44834、背景=5.28431。所有正 λ 都因缓存 DN 较高而未通过。原结果与五点规则保留，不事后放宽阈值。

作者在本轮明确要求优先研究自己的方法，避免严谨性流程挤占实际效果判断。因此在同一两小时总预算内，追加**已冻结原始提案的生成诊断**，最多 15 分钟：复用同一模型、原数组、gain、16 条任务行；仅 Native 的 8 条短问答作必要能力参照，本方提案测 8 短+8 长。不再跑 Mr/YaRN/CoPE，不修改 β/投影/参数，也不按生成成绩选择另一张表。

该臂单独命名 ScaleTransportUnguarded，输出到不同目录；它不是通过约束的 Pro 最终方法。问题是“缓存拒绝是否伴随实际能力损伤”。若无收益或损伤明显，结束这轮并分析已有文本；如有可用效果，后续再解释 guard 与能力的差别，不把此 post-construction 诊断冒充预注册独立确认。

原始提案的生成诊断已完成（66.97 秒）：Native 短面板 F1=0.49846，本方短面板=0.425，本方长面板=0.22202；每格 8 行，全部 EOS。它不能支持获益主张。

随后仅作一个已声明的中/尾段归因比较：MrMiddleScaleTail 保持 Mr 的 j<40 原频率，中低尾 j≥40 使用**同一已经固定的原始提案**，没有重新估计、投影、排序或调 gain。复用已核验的 8 条 Native 输出，只新增本方 8 短+8 长，最多 15 分钟且不突破同一个两小时截止。它检验大幅改变中段是否是短任务退化的来源，属于同开发集的 post-outcome 归因，不作为独立确认。第一轮 evaluator 的代码已在修改前归档，原 plan/hash 与原结果保留。

### 逐题结果改变了哪些判断

尾频组合相对 Native 的平均 F1 +0.024749，仅由两行组成：narrativeqa_3 贡献 −0.010965，narrativeqa_13 贡献 +0.035714，其余六行相同。后者 Native 已输出人名 Virginie Vervelle，尾频组合输出更长的“他们的女儿 Virginie”表述，参考答案包含 daughter 和另一种人名拼写。这不足以说明多学会了一题，不能把 F1 上升当作能力增加。

原始全中低频提案把 narrativeqa_19 的答案由正确的 Two 改为 One，恢复 Mr 中段后又输出 Two；它还把另一行的人名换成了不同人物。这给保留中段提供了具体开发证据。数量词 Fifty/50 的 F1 差异则不能当推理进步。这些是对已保存答案与参考的解释，没有修改官方词面评分，也没有另造语义分数。

长面板 0.222→0.225 同样没有显示清楚的增益；错误答案中的少量共有词也会拿到非零 F1。每个面板 8 行各有 5 个上下文，不应把相关问题当成 8 份独立文档证据。接下来不继续围绕这 16 行挑表。

### 原始尺度分配的具体问题

Mr 在 j=24 的累计指数约 0.0065，本方原始提案却给到 0.912，接近把该槽位从几乎不动改为 `/4`。类似变化遍布中段。因此它实际重写了 Mr 有效的高到低渐进分配，而不是在该分配上作小修正。

“真实增长减去固定内容裁切增长”的差分思路有消除纯可见性效应的优点，但现有未截断尺度比给出的差分范围为 −1.537 到 +0.541，40 个待考察槽位中 7 个绝对值超过 0.5。没有充分依据把它立即加到 Mr 指数上；那会启动又一轮剧烈移动。这次只将差分作为诊断，不把它包装成新最优规则交给 GPU。

### 只保留一个新组合

令 T 为本轮已经测试的 MrMiddleScaleTail 数组。使用 CoPE 官方推理代码的末 20 槽余弦衰减思路：

\[
c_j=1\quad(j<44),\qquad
c_j=\frac{1+\cos(\pi(j-44)/19)}2\quad(44\le j\le63),
\qquad \nu_j=T_jc_j.
\]

名称仅作实验标识：`MR_SCALE_TAIL_COPE20`。不改统计、gain、槽位数或边界；当前参考计算约定为 Python float64 cosine 后存 IEEE float32，不能称与 Torch cosine 逐位相同。[CoPE 官方实现](https://github.com/hrlics/CoPE/blob/f8957a1c7e4891f31266ca79299437a672175a1a/modeling_cope.py)

这里三部分各有用途：Mr 中段保留已有效的累计分配；现有本方尾频允许部分较快的低频保留位置变化；CoPE 衰减进一步稳定深尾。末频率变零仍保留该 Q/K 子空间的内容内积，不等于删除通道。组合不是已验证的新颖性，仅仅把两个已有方法相乘也不足以支持论文主贡献。

CPU 结果：前 44 槽逐元素不变，末槽精确为零，所有频率有限、非负、非增；继承的等频对如实保留。最终 FP32 tensor SHA-256：`a63fe2714b37a30b4387fff8af500c270b62770a5b90677302083569af9c2eb2`。

对比已测试的 T，最大附加频率变化出现在槽位 51，约 2.11834e−6。由二维旋转恒等式和块对角范数，连续距离区间 [0,L] 上有

\[
\sup_\Delta\|R_{\nu}(\Delta)-R_T(\Delta)\|_2
=\max_j2\sin\!\left(\frac{\min\{\pi,L|\nu_j-T_j|\}}2\right).
\]

在 Native 32K、目标 128K 上分别约为 0.06940、0.27676。这里不含共同 gain，比较的是相对旋转算子；不是最终 logits/生成误差界，也不能修复 T 已有的损伤。它说明这次新增干预集中在深尾部，不再像原始提案一样大幅重写中段。

### 下一步用什么实际终点

上一轮 NarrativeQA 小面板适合抓明显故障，却与 MrRoPE 原文的 RULER、InfiniteBench、LongBench-v2 不同，无法直接利用论文分数作方法对比。这一点应改进，而不是再增加许多同类自定义小面板。[MrRoPE §4.1](https://arxiv.org/html/2601.22181v1)

下一项具体比较应优先使用 Qwen2.5-3B、固定 s=4、真实 128K 输入，在原文对应的官方 RULER 任务上测**本方组合**。先少量、固定每任务样本进行开发筛查，保留任务宏平均，注明样本数/代码版本/精度与论文差异；论文对手结果先复用，不自动重跑完整基线。真实计时后再定下一批预算，不把先前约 60K 的吞吐直接外推成 128K 保证。

若组合出现有用结果，再补最小的 `MrPro×CoPE` 去掉本方统计的消融，判断自身分配是否提供了额外价值；这比先跑完整对手矩阵更直接。若只有恢复中段有效、长任务仍无收益，就保留发现并结束此候选，不以新 gain、更多窗口或未声明重拟合救分。

此阶段已经得到具体数组与可证的局部改动范围，但尚未得到新模型结果、可比论文分数或 SOTA 证据。服务器与监控保持停止，论文与 Git 历史未改。
