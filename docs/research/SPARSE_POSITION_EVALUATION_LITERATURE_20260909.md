# 稀疏位置方法：同类论文怎样证明有效，以及当前方案缺什么

2026-09-09。本文是原文实验核查和实验设计，不是本项目的新实验结果。
当前候选为「压缩前绑定源位置」。查询参考混合方案已退出当前主线。
用户随后明确的计算边界：现成模型最多微调；从零训练限于 150M/350M 量级。
现有约 319M 参数 Mini 属于这一量级；更大的从零预训练不在本项目当前执行范围。
当前候选继续推进；初期工程故障或尚未学会任务不能触发自动换方法。
已收到并审阅用户指定的 [Qwen 综合建议](PROJECT_DIRECTION_SYNTHESIS_20260909.md)。
本文末尾记录与当前证据的核对；保留原报告不改写。

## 结论

有可操作的验证方法，但目前没有证据证明我们的候选优于已有方法。
仅在自制顺序题上超过自己实现的 block-anchor 基线，最多证明一个局部效应。
可信的主要结果应是：相同资源下，强基线与候选在公开任务上的质量比较，
再用反事实任务解释增益；或者相近质量下的实测成本改善。

300M 随机初始化模型可以用于机制实验，但没有经过足够语言训练时，
直接要求它完成 MRCR 无法有效检验位置方法。参数量小不等于已经具有语言能力。
这不意味着必须先完成昂贵预训练才能探索；意味着小实验的结论必须停在其支持的范围。

## 原文核查

### PPE：同一压缩方式、同一压缩率，比较位置保留

来源：[PPE v1，§4.1–4.4，Table 1/4](https://arxiv.org/html/2510.22936v1)。

- 默认 Qwen2.5-VL-3B-Instruct。图像约 300K 样本、视频约 120K 样本，分别全参数 SFT 1 epoch。
- Dense、Chat-UniVi、Chat-UniVi+PPE 在相同实验设置中比较。空间压缩 55%，时空压缩 94%。
- Table 1 图像平均 75.90→81.15，Dense 82.09；TextVQA 57.66→77.14。并非每个单项都胜出。
- 另在 Qwen2-VL-7B 的 PACT、ToMe 上测试可迁移性；该部分区别于上述经过 SFT 的主表。
- Table 2 汇集不同原论文的模型成绩，不能把它当作固定训练条件下的位置因果比较。

可借鉴：在既有压缩算子上添加位置方法，固定压缩预算，保留 dense 参考，测多个任务。
边界：PPE 是视觉 token 多位置 ID 分配；移植到文本压缩时必须标为 PPE-inspired adaptation，不能冒充原版复现。

### RoVE：小模型可以研究，但原文检索证据不是完整生成

来源：[RoVE v1，§4、Appendix A.1](https://arxiv.org/html/2606.11275v1)。

- 124M、354M GPT-2 风格模型，各条件 FineWebEdu-10B 训练一轮，训练长度 1024；4 张 H100。
- RoPE/RoVE 只改变 value 路径，其他架构和训练超参数保持一致。另作 ±YaRN 对照。
- DCLM-Core 测训练长度内能力，长长度测 PPL，4K/8K RULER 四类任务各 500 样本。
- RULER 明确使用答案 NLL；其 ± 是样本标准差，不是多个训练种子的误差。

可借鉴：两个规模、固定训练条件、标准下游任务与位置机制相联系。
边界：不能把其 NLL 改善称为 exact generation 成功，也不能因为论文这样评分就降低本项目的完整输出要求。

### Prism：优势是质量与预填充成本的联合比较

来源：[Prism v1，§3.2、§4、Appendix 8](https://arxiv.org/html/2602.08426v1)。

- 无训练，Llama-3.1-8B、Qwen3-8B，以及 Qwen3-VL-8B；覆盖 PG19、LongBench、RULER、视频任务。
- 比 Full Attention、MInference、FlexPrefill、XAttention；基线用官方推荐设置，并非主表所有方法严格等密度。
- 单独报告 H100 attention prefill 时延与 selector 开销，另外做 PPL–density 消融。
- LongBench：Llama 的 Prism 41.08、MInference 41.14、Full 41.47。不能说 Prism 的任务成绩全面第一。
- 因此本项目若借鉴该范式，应测质量–预算/时延曲线，明确 attention kernel 与整个模型的时延区别。

直接挑战当前候选：该文分析了先旋转再平均引起的相消。保留源相位不自动等于更有用的摘要。

### NSA：原生稀疏架构的完整证据需要真实训练

来源：[NSA v1，§4.1–4.3、§5](https://arxiv.org/html/2502.11089v1)。

- 27B 总参数、3B 激活；Full Attention 与 NSA 均训练 270B tokens，8K 后继续长上下文训练/SFT。
- 一般能力、LongBench、推理，以及 forward/backward/decode 效率分别报告。
- 长上下文基线包括 H2O、InfLLM、Quest、Exact-Top；激活 token 数设为 2560 对齐稀疏预算。
- NSA 压缩器本来就有块内位置编码，不能把「压缩保留位置」说成此前无人处理。

可借鉴：共同训练配方、强稀疏基线、质量和成本同时测。
边界：Mini 的短训练试验不能称为复现这个证据规模；激活 token 相同也未必代表总驻留 KV 字节相同。

### Still：压缩后的能力、训练公平性和生成验证分开

来源：[Still v1，§2.2–2.5、§3、Appendix E/G](https://arxiv.org/html/2606.07878v1)。

- 冻结主模型训练 compactor；比较 H2O、SnapKV、StreamingLLM、Attention Matching、KV-Distill。
- 核心比较固定最终 cache 大小；Still 与 KV-Distill 匹配训练，分别测同分布 holdout 和未训练任务迁移。
- 主要 frontier 和 RULER 报告三个训练种子；部分生成和递归压缩结果为单种子加样本 bootstrap，明确区分。
- 训练使用答案侧 teacher KL；生成部分另测 HELMET 和 LongBench 总结，不把训练 loss 当生成成绩。
- 单次压缩先产生完整 KV；文中区分保留 cache、压缩时峰值与完整预填充成本。

相关风险：Still 先逆旋转 key 到内容空间再压缩，重设输出位置，并报告混合已旋转 key 的不稳定。
这是另一个需要解释的竞争方向，不直接证明我们的原生局部压缩一定失败。

### TAPE：机制任务与语言任务组成两层证据

来源：[TAPE v2，§5.1–5.4](https://arxiv.org/html/2501.00712v2)。

算术实验用所有输出数字 exact match；语言部分有 C4 预训练后 SCROLLS，
以及 Llama2-7B 的上下文扩展、PPL、passkey，并与 RoPE/ALiBi/FIRE/xPos 等比较。
这支持「机制实验 + 公开任务」的证据组合，但不能推出任何单独算术胜利就是通用语言能力胜利。

### FASA：稀疏访问与真正压缩不是同一预算

来源：[FASA v1，§4.3、§5、Appendix D](https://arxiv.org/html/2602.03152v1)。

FASA-C 保留完整 GPU cache，通过频率子集筛选减少访问；FASA-M 涉及 CPU offload。
其固定选中 token 预算的成绩不等于同样多 token 的永久 KV 压缩成绩。
本文也不沿用其把 full-cache task accuracy 称为绝对 upper bound 的措辞：稀疏化可能偶尔提高任务成绩。

## 当前候选必须正面回答的反例

当前实现的局部压缩形式为：

    native:    C_b = R(p_b) Norm(sum_j a_j ⊙ c_j)
    candidate: C_b = R(p_b) Norm(sum_j R(p_j-p_b)(a_j ⊙ c_j))

仅旋转原有 partial-RoPE 维度，a_j 包含原生门控及其块内位置机制。
位置绑定并非无损保存所有来源。固定均匀标量 gate、一个频率对内 c_j=c 时，
归一化前幅值相对内容均值的倍率为：

    |sin(B*omega/2) / (B*sin(omega/2))|.

这是 Prism 已讨论的几何和，不是本项目新定理。它可以接近零；RMSNorm 不能恢复已相消的信息。
实际 gate、内容和 learned Norm 会改变表现，因此这是明确反例和诊断方向，不是实验结果。
本候选可能改善 source/order binding，同时损害纯内容检索；两者必须同表出现。

## 建议的验证设计：先决定是否值得扩展，再构建主要证据

这是一份待实施协议，不是已经准备好的 GPU 训练任务；不据此让 GPU 空转。

### 小规模的继续/停止实验

1. 使用同一 Mini 架构、共同初始化和数据顺序，只改变压缩位置操作。
   原始 replica 与修正后的共同运行实现分开；indexer 训练等修复必须同时进入全部条件。
2. 主对照保留原生块内 learned position/gate 和 block-anchor RoPE，不能拿去掉原生位置能力的弱基线代替。
3. 任务同时覆盖普通 key-value 内容检索、重复 key 的第 n 次/最近一次读取，以及交换事件顺序的成对反事实。
   训练/测试按内容和模板分离；因果顺序标签与完整答案由生成器直接确定。
4. 在同样的短任务训练下用自由生成完整答案加 EOS 测试；loss 只用于训练诊断。
   报告全样本成绩与反事实成对成功率，不筛选有利样本。
5. 检查原生 baseline 是否学会普通内容检索。若全部条件都没有基本能力，实验对位置优劣不具诊断性。
6. 首个配对种子只决定是否值得继续；若有稳健效应，扩展到多个配对训练种子与未见长度/块边界。
   不把三个种子机械当作充分统计证明；报告每个种子的差异和样本不确定性。

初期未改善、训练不稳或基本任务未学会时，应先检查训练是否充分、数据监督和实现是否正确，
在相同配方下修复基线和候选，保留检查点、训练曲线与已完成的有效比较。
这些问题既不证明方法有效，也不足以否定方法；不能因此自动切换候选。
只有在实现正确、训练充分且对照公平的条件下，持续没有顺序收益或显著损伤内容能力，
才据此决定停止当前构造；修复或调整必须指向已定位原因，不能无限盲扫参数。
若候选没有改善成对顺序成功率，或增益伴随显著内容能力退化，就不能宣布解决压缩位置问题。
即使通过，这一阶段仍只支持该 Mini 设置下的机制收益。

### 能够支撑主要论文结论的比较

- 在一个具备基本任务能力的、实际压缩模型中，用共同训练/适配配方比较 native 与 candidate。
  当前 random-init Mini 不满足「现成的预训练模型」条件；所需训练量与费用尚未测定，不能提前承诺小成本完成。
- 除 native 外，至少纳入适用于同一压缩接口的多位置保留强对照。
  PPE 的频率分段多 ID 思路可做明确标注的文本适配；还应比较相同总 cache 字节下多摘要槽策略。
  RoVE 是相关已有算子，V4 自带 OV 旋转时不能把其原生操作冒充新加的独立对照。
- Prism/FASA 是选择型接口，直接把它们塞进 pooled-memory 的内部消融不公平。
  若主张跨稀疏方法整体更优，才在外部质量–成本比较中加入这些方法，并保留各自必要的完整 cache/selector 成本。
- 公开任务采用 RULER 和适合模型能力的 LongBench 子任务；主张重复来源能力时加 MRCR 或可追溯的事件绑定任务。
  MRCR 是该主张的相关任务，不是所有位置编码论文都必须使用的唯一标准。
- 公开 benchmark 按官方指标报告；需要精确检索的任务另加 raw-output exact+EOS。
  QA/总结等开放式任务使用相应任务指标，不能强求唯一字符串，也不能用这些指标替代精确检索证明。
- 至少比较两个有实际区别的压缩预算。记录总持久状态字节、峰值显存、预填充/生成时延、训练成本。
  如果只在固定 Mini 中胜出，结论只限于该设置；跨架构 claim 需要另一个压缩接口的迁移结果。

因此下一步不是再发明一套指标，也不是再换研究主线；是用强原生基线、
成对顺序任务和内容任务判断当前位置操作是否值得投入公开任务实验。

## Qwen 综合建议：接受诊断，纠正研究裁决的证据跨度

接受其对强基线过晚、失败后不断新增解释、用代码和文档数量代替任务收益的批评。
预先明确什么结果会改变下一步，优先做能决定投入的比较，而不是再增加候选。

但不能直接接受其「cache-schedule 新颖、零成本、管线全就绪，指定为主线」结论：

1. BM 交叉缓存的两个静态位置表案例支持「读时重旋转不能一般性恢复前缀形成状态」。
   它们不是动态分块导致任务失败的证据。后者当前只有 toy 数值反例，不能接成已验证的完整能力因果链。
2. row-wise 的分块一致性证明成立，不意味着与最终长度规则生成同样状态，也不保证答案更好。
   静态规则同样分块一致；若静态控制质量/成本相当，这项性质本身不构成方法优势。
3. 零训练不等于零成本：现有实现重旋转历史 K，并按 G_t 分组执行 attention；额外旋转和 kernel 成本尚未实测。
   当前 install 仅审查 Qwen2/3，不能以此宣称跨 checkpoint 无条件可用。
4. 更直接的数据问题：现成 MRCR 长输入为 18,093–25,105 tokens，构造时明确限制在 32,768 原生窗口内。
   若 W=32,768，整批输入及其生成预算不会触发 G_t>1，因此不能用于裁决原生窗口之外的动态 schedule。
   把 W 人为缩成 128 可作算子诊断，但不能当作模型真实上下文扩展证据。
   证据：[数据 manifest](../../results/reference_position_20260909/mrcr_pairs_dev/manifest.json)
   与 [probe 默认值和实现](../../experiments/rope_operator_family/cache_schedule_probe.py)。
5. 「native MRCR 卡在 SDPA」已经过时：重新通过 SSH 读取 native_baseline_02/status.json，
   status=COMPLETE，48/48 条，226.785 秒；修复未要求升级原环境 PyTorch。
   完成的是原生基线，不是任何候选的位置收益。当前 probe 仍有 schema 和模型后端验证工作，不能称全部就绪。
6. RefCarry 近邻重合否定宽泛首次性，不能单凭重合推出部署改进不可能；
   同样，少量负样本仅限制已测试条件。「杀死候选」应落实为停止当前投入，而非没有证据的全称不可能。
7. 该报告以讨论中的一个时点为快照，未覆盖之后 DeepSeek Mini/source-binding 的讨论。
   它的路线建议不是用户已经选择路线的证据，也不能据此把稀疏压缩 PE 目标自动收窄成动态外推问题。

实际决定：cache-schedule 可以是优先级较高、无需训练的有限判别实验，前提是已有明确的增量场景目标。
它不能在结果之前被升级为论文主线，也不能在 row-wise 失败后自动接上 normalized-reference 来维持原主张。
source-binding 也继续保持未验证候选身份；其优先性不能靠最近写了代码或换了模型来证明。

### 值得采用的内容

- 把稀疏选择、压缩摘要、value 读取和位置编码共同考虑，贴近用户原来的广义稀疏 PE 目标。
- 最终任务质量与机制诊断分开；同时报告总缓存字节与实际推理成本。
- 固定 K 与固定稀疏 mask 是两个实验：前者允许路由改变，测系统总效应；后者固定可见内容，帮助定位读取效应。
- 内容检索、顺序/来源绑定、一般语言能力分别测。不能把 NIAH 成功当成长程推理成功。

### SparseGraph-PE 的核心动机存在两处跨越

1. [DeepSeek 官方公告](https://huggingface.co/deepseek-ai/DeepSeek-V3.2-Exp)
   确认 indexer 输入应使用 non-interleaved 布局，MLA 则用 interleaved。
   修复是让各路径符合其权重的约定，并非把两条路径统一到相同布局。
   不同基底下正确实现同一旋转可以保持同样的内积；该 bug 不能证明独立位置几何本身有害。
2. [DeepSeek-V3.2 §2，Eq.3–4](https://arxiv.org/html/2512.02556v1)
   已用主注意力 head 聚合分布监督 indexer：dense warmup 后在 selected set 上继续 KL 对齐。
   indexer 输入 detach，indexer 只由该 loss 优化，主模型只由 LM loss 优化。
   因此报告中的 router–main consistency 概念不是空白。
   提案写的反向 KL 或 position-only ranking 不是与原方法完全相同，但仅换方向不足以论证新颖性或收益。

要让这个方向成立，必须证明：在正确官方位置实现、已有 indexer 蒸馏之后，
仍存在可定位到位置因素的系统误选；然后比较新增操作与既有训练、等容量内容 scorer 的差别。
目前报告没有提供这项证据。

此外，任意 edge-type phase 不一定能写成每个 token 各旋转一次的形式。
若要求 phase_ij=a_i-a_j，则对有方向的三点路径必须满足
phase_ik=phase_ij+phase_jk (mod 2π)。任意加 edge-type/block-scale 项未必满足。
它仍可以作为逐边算子实现，但需要说明缓存、kernel 与成本，不能从参数少推出工程开销小。

### 压缩位置分布是相关问题，但边际位置统计不等于内容–来源绑定

报告建议保存位置均值、方差或 Fourier moments。这个方向直接相关，但这些统计不自动解决来源绑定。
在一个固定输入特征的对照中，A@p1/B@p2 与 B@p1/A@p2 有相同的内容均值和位置边际分布。
若压缩只保存两种独立均值，就不能区分交换；完整网络的上下文特征可能编码额外信息，故不是全网络不可能性证明。
联合统计 sum_j R(p_j)c_j 可以对这种交换敏感，但也有上一节的相消反例。
这为当前 source-binding 候选提供了一个明确的比较问题，而非已经验证的优势。
PPE、Prism、RoVE 和现有 learned positional gates 必须进入最近邻分析。

### 另外两条提案和预算的边界

- PhysicalRoPE 的「frame index 改物理时间」不能作为首次性：
  [Qwen2.5-VL §2.1.3](https://arxiv.org/html/2502.13923v1) 已把 MRoPE temporal IDs 对齐绝对时间，
  并使用动态 FPS 训练。跨模态、尺度几何仍可研究，但必须指出超过这一已有实现的具体差别。
- Positional Scaffolding 自己也承认 DroPE/R2N 邻近；可学习 gate 是候选实现，不是已确认的新主张。
- routing corruption curve 可作补充鲁棒性诊断，不能保证位置机制特异性。
  替换边会改变是否还有正确内容可读，需要分开记录可恢复信息、自然路由误差和人工扰动。
- 报告按 8×A100、1–2 周、1300–2700 GPU-hours 设计，不能转述为当前单卡的小成本方案。
  3–5 分增益等是作者设定的目标，不是从样本方差或部署价值推出的充分标准，更不是录用保证。
- 关于「RoPE 长度增大后趋近 0.5」：
  [原文](https://arxiv.org/html/2605.15514v1) 分析的是给定 Q/K 的位置/相关性排序事件，
  依赖其概率建模假设；不能直接解释成任意训练模型的完整任务准确率会趋近 50%。

### 两份报告合并后的研究判断

第一份的执行诊断有用，但不能把便于测试的 cache 一致性问题自动设为新主线。
第二份给出的稀疏/压缩问题地图更符合用户目标，但 SparseGraph-PE 尚未从既有 DSA 对齐中分离出新贡献。
维持当前问题：在固定资源下，压缩位置机制能否更好地保留内容与来源/顺序的对应关系。
当前压缩前源位置绑定只是这个问题的一个候选；用 native、边际位置统计与联合绑定的清晰对照判断它。
不同时启动三条新路线，不把任何报告的推荐等级或论文标题当作正结果证据。
