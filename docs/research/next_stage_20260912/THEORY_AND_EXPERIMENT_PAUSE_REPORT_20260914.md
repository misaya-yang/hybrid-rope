## 1. 阶段结论

本轮有实际收益，也有明确代价；没有建立一个由理论确定参数、且稳定超过
YaRN/MrRoPE的完整新方法。mix075的0.75系数、当前band和gain仍含经验选择。
不能把这些选择倒写成由现有定理推导，也不能因为理论未闭合而撤销真实正结果。

最重要的未完成项，是把预训练模型**实际需要保持或改变的计算**转成构表约束。
现有几何、局部导数和代理最优解，尚未完成这个连接。继续扩大同一面板或换曲线
不会自动解决它，因此当前暂停新增实验是研究收束，不是认定z方向失败。

论文主线保持：z发现 → EVQ → full-z → 成熟模型上的z变化及相对强基线结果 →
更有依据的理论。全窗口评价用于衡量收益与代价，不替代三个设计问题。

## 3. 理论已证明什么、没有证明什么

完整证明、数值反检和构造公式见
[功能约束与z迁移分析](ROPE_FUNCTIONAL_CONSTRAINTS_AND_Z_TRANSPORT_20260914.md)。

**第一，当前mix075的改动方向已明确。** 同band内部逐槽有
`m_mix075 > m_BM > m_MrPro`，所以其频率逐槽更慢。Llama band中点的mix/MrPro
频率比为4×时0.56294、8×时0.42237。不能把它解释成更保护Native中频的构造。
这证明干预方向，不证明FWE损伤的唯一原因。

**第二，/S不是从RoPE公式自动推出的任务最优终点。** 对已识别的抑制性分量
`-sin(nu*d)`，在`[0,H]`不变正的精确条件是`nu H<=pi`；只允许减速且要求最接近
Native时，唯一解为`min(omega,pi/H)`，仅特定条件下恰好为`omega/S`。对正余弦
内容分量，相应边界变为`pi/2`。这证明功能约束不同会产生不同终点，不证明当前
checkpoint应统一改为其他除数。

**第三，已识别的功能区间可以给出解析构造。** 若每槽允许的指数范围为
`a_k<=m_k<=b_k`，且要求单调m，则逐坐标最小解为

    m*_k = max_(j<=k) a_j.

可行当且仅当每个`m*_k<=b_k`。零平台、末端和中间过渡均由约束决定，不需要
再猜三个形状参数。但目前尚无足够的checkpoint功能识别输入，不能用短文本
平均复系数、范数或失败代理替代这些约束。

**第四，固定缩放指数跨倍率，不等于固定分配坐标。** 两端给定后，band内
归一化log坐标为`u=(A t+ln(S)m)/(A+ln(S))`。保持u的唯一倍率迁移为

    m1 = alpha*m0 + (1-alpha)*t,
    alpha = ln(S0)*(A+ln(S1)) / [ln(S1)*(A+ln(S0))].

Llama `[16,34]`从4×到8×得到alpha=0.757685348，无需搜索。但这是变量控制
公式，不是性能最优性定理；它继承的0.75父表仍是经验选择。u是band内部坐标，
不能冒称整谱z被固定。

**第五，已经否决一个看似可用的性能保证。** 上述迁移使中频更接近Native，
连续lag旋转误差上界不增加；但实际Llama全部17个中频槽的上界都已饱和为2。
因此它不能预言Native恢复。本轮没有因为这个无区分力的上界而启动新实验。

CPU验证覆盖这些代数关系、尺度迁移复合一致性、相位区间例子，以及1000组小型
区间约束的穷举核对；全部通过。CPU验证不等于模型验证。

## 4. 三个研究问题的最终状态

| 问题 | 当前成果 | 尚缺的关键环节 |
|---|---|---|
| 高频保持区边界 | 分清几何锚点与功能边界；给定功能区间可解析求活跃边界 | 当前checkpoint哪些槽承担何种必要功能，尚未识别为可靠约束 |
| 低频终点 | 已证明/S只在特定合同下最优；旧tail负例不能证明永久最优 | 没有经行为验证的checkpoint终点选择准则 |
| 中频过渡 | 有mix/BM/MrPro精确排序、固定u唯一迁移及现有正负结果 | 0.75与gain未由理论确定；没有独立确认的普遍胜出或预测准则 |

问题分别可提出，但实际功能约束与模型使用会产生耦合。不得把当前第三问的经验
进展写成第一、第二问已经解决。

## 5. 为什么此前理论没有有效推动实验

1. 把参数恒等式或任意代理的最优性，误当成真实任务的设计原则。
2. 推导之后未检查其在真实频率和窗口下是否仍有区分力；上界饱和就是本轮实例。
3. 有符号内容、竞争key、value与下游读出被几何量/范数压缩掉，无法决定改动方向。
4. margin/CAL局部改善缺少可重复的独立任务收益，后来仍被旧文档当作默认路线。
5. 构造、gain、开发样本和确认样本的作用混在叙事里；报告先称赢，追加块后再收窄。

这些是研究方法的问题，不意味着所有既有实验白做。现有数据已经排除了若干过强
解释，给出了有价值的配置和反例；应保留它们，而不是继续填满队列来回避理论缺口。

## 6. 本轮评测吞吐复盘

Qwen确认队列沿用了评测器默认`--batch-size 1`。这不是模型或Flash attention不能
并行：当前实现已经支持对连续、等prompt长度且等输出上限的行执行批量greedy；但本次
启动命令没有显式传入batch参数。Qwen 32K运行只占约5--6GiB，因此后续同类小模型
应先用`--batch-size 2/4`短canary比较吞吐和峰值显存，再冻结最大稳定值。Llama 64K
约占31GiB，仍应保持单模型、单长窗串行，不能把小模型策略机械套用过去。

最后72条Native在发现该问题时已经接近完成。为保持runner身份和避免拆分、重复及
合并风险，本轮没有中途重启；它已自然完成。这个选择不证明现有默认值合理，只是
尾声收束的风险控制。
