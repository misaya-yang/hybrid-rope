# 下一阶段：从分配自由度到可学习、可解释的设计

更新：2026-09-12。**按科学价值和判别力安排，时间与机器资源由作者协调。** 本文件是主代理综合计划，吸收理论、实验、论文三个独立子代理的审查；计划与已完成结果严格分开，当前执行回执见“状态与依赖”。

## 先读结论

当前论文已建立：内部指数分配组织有限位置基，权重学得使用它，具体构造能产生实际收益。下一阶段最值得增加的认识是：

> **在相同频率支持内，解析先验和训练损失分别会选择怎样的位置基？模型怎样学得使用这种分配，哪些结构能够迁移到新的长度和任务？**

保留现有论文标题和三段主线，推进“可识别的变量 → 可学习的设计对象 → 可检验的使用机制”。资源优先投入完整配对、充分训练、机制干预和独立验证；不因假定截止压力退回短smoke，也不因机器多堆曲线和benchmark。

## S1 主实验：固定支持下的解析分配与直接学习

### 科学问题

A01已证明只改内点有作用，A02表明多个形状有价值。新实验要回答：标准短窗语言建模目标会把内点学到哪里；它与解析Cosh相比在训练窗口、长端及训练成熟度上有什么差异。重点是学习选择和长度行为的关系，不能只以learned是否击败Cosh判成败。

### 推荐主合同（待实施前锁定）

| 因素 | 推荐设计 | 判别作用 |
|---|---|---|
| 模型 | 151.9M量级、K32，实际连续L=2048 | 桥接256严格识别与实用学习窗口；不注入虚拟长位置 |
| 表 | fixed Geo、fixed anchored Cosh、Geo-init full-z与全部权重联合学习 | 解析先验与目标驱动学习；共享跨层/头的K−2自由度 |
| support | 预指定B=2048与B=500000两个block；每block内最高/最低频率、log-span、K完全一致 | 分辨接近训练窗的较窄支持与慢端更长的支持依赖；两个block之间不声称纯z |
| Cosh强度 | 初始建议tau=64/sqrt(2048)=sqrt(2)，两support相同，开封OOD前锁定 | 固定参考构造，不用每个block事后最优tau |
| 重复 | seeds42/137/256；同seed×support的初始权重、文档顺序、优化器、全局token batch、预算配对 | 训练seed是独立重复；提示不能冒充seed |
| 成熟度 | 建议1B-token预定轨迹，保存共同500M与1B checkpoint；所有臂相同最终budget/schedule | 直接检验早期增益是否随学习持续，不能跨旧实验归因；1B不是收敛保证 |
| full-z实现 | 正gaps归一化累积、端点精确、次序固定；allocation LR/decay/数值保护预先锁定 | 不隐形继承旧oracle的±2投影；说明是否限制设计空间 |
| 评价 | 独立文档/pack，2/4/8/16K全序列NLL和末128 NLL，预指定OOD等权汇总及窗内代价 | 不选最佳长度；重复文本或共享训练stream不能冒充独立holdout |

两support×三方法×三seeds = **18条完整训练轨迹**；若锁定1B合同，为18B训练tokens。这里只登记可调度的科学工作量，不估未经实测的GPU小时。确切架构/head_dim、数据和训练版本需从恢复后的实现核对；若d_head不同，tau公式必须明示使用哪个量。

**运行准备有明确终点**：uniform初始化与固定Geo前向一致、端点/排序正确、allocation梯度有限非零且optimizer更新、sin/cos缓存保留计算图、实际token吞吐/显存可行。通过后进入完整训练，不反复以CPU小检查代替模型结果。共同训练预算和LR在OOD开封前确定，不能只延长落后臂或按第一个seed输赢挑超参。

### 资源增加时最值得扩展什么

1. **初始化与可学习性的2×2**：补Cosh-init full-z，与现有Geo/Cosh fixed以及Geo-init learned构成因子设计。它区分解析初始化、自由度与训练路径，比再加一条手工曲线更有内容。若在两个support/三seed全补，为6条额外轨迹；是否作为主合同一次锁定由希望回答的路径依赖问题决定，不等看到不利结果才补救。
2. **4K实际窗口**：在预指定B=500000 block复做三表×三seed，保持support和tau=sqrt(2)，评价4/8/16/32K，增加9条轨迹。检验窗口因素；若tau改为1，则明确检验随窗口变化的默认设计规则，不能同时声称只改变window。
3. **重复与独立数据**：效应区间仍同时容纳有用收益和实质伤害时，增加训练seed或独立文档。不要用更多模型替代不充分的配对重复。

扩展由科学问题决定，可利用多机同步推进；既不因“太晚”自动删掉有价值的对照，也不因某个seed阴性取消预先确定的比较。

### 不同结果增加什么知识

| 观测 | 可以推进的认识 | 还不能说什么 |
|---|---|---|
| learned同时改善窗内/长端 | 分配可由任务目标进一步优化 | 不是所有support/模型都存在同一最优表 |
| learned窗内好、长端弱于解析 | 学习目标与长度设计先验偏好不同 | 不能只凭此认定梯度机制或短窗loss是唯一原因 |
| Cosh与learned相近且区间够窄 | 简单解析构造有实际竞争力 | 点估计相近不等于统计等价 |
| 不同support偏好不同 | 分配设计需要联系供给尺度与运行范围 | 两support之间的总效果不是pure-z估计 |
| 500M优势到1B缩小/扩大 | 同合同下的训练成熟度关系 | 中途500M点不是旧500M终止schedule的严格复现 |
| 新设置Geo更好或差异小 | 确认已有结论的条件结构，保留完整结果 | 不扩大为内点无用或整个解析构造无效 |

## S2 机制主线：在同批模型中连接位置基与实际使用

机制工作与S1共享模型、数据身份和早/中/末checkpoint，避免另起一套玩具模型给论文主结果作解释。

1. **供给层**：同一表计算raw Gram、block-whitened overlap、去掉低阶公共方向后的剩余谱；固定uniform/causal-triangular等预定距离测度。它们回答方向数与系数尺度，不直接预测loss。
2. **学习层**：做weights×table crossing；fixed Geo/Cosh/learned三表与三个配对权重的3×3是冻结推理比较。保留完整矩阵和本表结果，避免只解释赢家；learned最终表由对应seed定义。
3. **使用层**：在实际能完成基础检索的同一模型/匹配读出协议上，固定内容、答案与解码，改变证据距离。记录pre-RoPE Q/K、精确有限相位logit变化及evidence/distractor odds，同时记录完整答案与终止。全局平移所有position IDs不能替代相对gap干预。
4. **因果确认**：独立样本上，使用预定的band/层组双向移除与恢复、sham和路径对照，检查任务收益是否随干预改变。选择head/层用独立开发集并锁定，不能按测试答案挑贡献；禁止把答案方向logit强推当“机制恢复”。

odds公式本身是标准softmax代数，价值来自模型中何种频率—内容关系确实承载收益。只有attention图或首token odds变好，完整输出没改善，不能宣称机制闭环。任务地板先修具体的读出/数据问题，不把地板当理论否定；若新匹配readout训练引入了新适配器，明确它是独立协议。

理论报告的三个可交付件分别处理：**系数预算下的可表达性**有机会连接学习，完成严格条件和实际系数检验；**锚定后的准确密度身份**提高方法清晰度，主要入附录；**有限Cosh目标**只有导出并验证有限K的新预测才升为主文贡献。不要为了理论数量增加一个无法检验的泛函。

## S3 既有核心结果的完整性与独立验证

这是与S1/S2并行的证据工作，不因“只是复评”而忽略其科学价值。

- **151M绝对四格**：定向追回原evaluation JSON、anchors和checkpoint，按现有raw hash/科学合同核对。找到checkpoint而缺JSON时可重评原anchors；没有原件就保留已确认配对差，不从差值解出四个绝对值。
- **MLA独立语料复评**：本地`results/eval_3seeds_full_results.json`的SHA已与curated owner对上，但这没有证明旧cache独立。若六个final checkpoint可用，锁定能证明未参与训练/选型的文档/pack、版本与token hash，复评8/16/32K，保留原生窗代价。先每seed聚合NLL再指数化；seed与文档不确定性分开。
- **原始生成归档**：沿EOS/QK/C2回执找token IDs、EOS/cap、表与适配器身份。可达性、哈希核验和任务重跑是不同状态，不假装compact receipt含全部原始生成。

资源重点是原件、checkpoint和独立长文档，不默认重训所有历史模型。旧实验目录的服务器状态本轮未查询。

## S4 成熟设计结构：两个互补问题分别确认

**C42与C2不是竞争结论。** C42说明同一总量未涵盖全部形状信息；C2说明一个有效表仍可以有紧凑描述。下一阶段分别检验它们在开发面板外是否稳定。

| 比较 | 问题与必要控制 | 结果如何进入论文 |
|---|---|---|
| C42/C42V24独立生成 | 锁原两构造、同support/band/Σm/质心/实际gain/decoder；新提示与旧350选择面板隔离；同任务分布先确认，任务分项和EOS完整报告 | 方向稳定则把同预算结构从开发发现推进为独立确认；反转则报告新结果并限制该具体预测。step42历史反转不是此对照的负复现 |
| C2固定规则任务迁移 | 固定两参数、64点参照表、gain和transport，Qwen不重拟合；独立检索与自然QA，原生32K及64/128K长端分列 | 检验紧凑描述能否保留新的长任务用途，同时报告native代价；不以重新调参数挽救失败 |
| BM/MR×gain完整析因 | untouched同一面板四格；单位gain与登记YaRN gain；Native/officialYaRN作为有用参照，各自身份固定 | 逐提示difference-in-differences识别表与gain交互；350/180面板不拼接。Qwen Native/Index旧代码不是BM/MR对照 |

资源足够时可并行，但各项各自锁定问题和判据。C42优先服务“总量之外的形状结构”，C2优先服务“可迁移的紧凑设计”，gain服务“部署条件的交互”；哪项成为正文重点由完成后的实际证据决定。无信息地板、宽区间和实质负结果分别处理，不重开任意curve/gain搜索。
