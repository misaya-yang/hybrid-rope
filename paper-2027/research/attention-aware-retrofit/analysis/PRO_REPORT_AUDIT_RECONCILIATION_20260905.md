## 1. 接受的纠正，以及旧快照不能继续使用的结论

Pro 的关键纠正成立：double 的 compact 合格数 4<8，限制多证据迁移的可识别性和精度，不足以否定单证据比较或固定表的 Native restoration。数据真值、split、cache、加载、数值等共享缺陷才应停止所有受影响实验。原来的全局停机范围过宽。

## 2. 第一性原理：为什么优先补对照，而不是立刻修 loss

严格成功可在适用任务上写为 C ∧ F ∧ E：答案内容正确、形式合规、正常终止。仅观测严格分数变化不能识别三者分别改变多少；即使 far 比 near 改善更大，也可能是位置相关的格式修复。自然 QA 的 gold 字符串出现不能作为内容正确判据。

现有训练同时改变了任务熟悉程度与长输入 exposure，尚无短输入适配的反事实。因此 N_compact 的信息价值高：保持目标序列、语义实例、更新和 replay 相同，仅替换输入，才能估计长输入 exposure 的增量。该处理同时改变背景、位置及输入成本，不能再细称纯距离／相位效应。

换表问题还缺同一个 Qwen 上的 Z0→Z_transfer、Y0→Y_transfer。OLMo 冻结失败与 Qwen Native 表训练成功不能拼成换表恢复因果链。即使 Z 适配成功，与 Y 的不同幅度／支持仍使其属于系统比较，不能直接归因为 allocation。

遗忘方面：有限 truth-prefix KL 只约束采样状态的分布；greedy 输出取决于沿途每一步的 argmax。若某个 teacher 前缀的正确 token margin 为 m>0，且所有词表 logits 的扰动绝对值均小于 m/2，则这一决策不变；沿完整 teacher 轨迹逐步成立时，可归纳保证该轨迹不变。当前平均 KL 并未证明这种逐步条件，尤其未覆盖 teacher 实际路径。因此“小平均 KL + 少数决策退化”并不矛盾。实际 teacher 轨迹 replay 是有针对性的假设，但仍是有限覆盖，不提供普遍保证。

答案 labels 少不等于上下文没有梯度。Prefix-LM 增加的是背景预测目标；不能由标签占比推出它必然修复检索、FFN 或遗忘。固定 mask 的固定参数无偏恒等式，也不是整段自适应优化轨迹的无偏保证。

## 3. 修订后的有限实验顺序

| 顺序 | 比较及其唯一主要问题 | 固定内容／结果如何改变下一步 |
| --- | --- | --- |
| A，CPU 优先 | 旧自然验证输出的内容／格式／EOS 转换 | 保留 strict scorer；隐藏臂身份，先冻结语义 rubric，歧义显式标注；当前属于回顾性诊断，不冒充独立盲评 |
| B，首个新训练 | N_compact 对现有 N128：长输入 exposure 是否必要？ | 原始 Qwen、Native 表、seed42、all-linear r16、32R+96T、768 views、同目标及 replay 日程；prefix off；最终 step128 固定，不重选保存点 |
| C，两个候选 | 同 Qwen 的 Z0/Z_R32/Z128 与 Y0/Y_R32/Y128：换表后能否恢复？ | 复用旧 loss、数据、预算；读取各自 Qwen manifest 的表与幅度；Z 从原始 checkpoint 重启，不续接 Z26；R32 只作机制诊断，不事后选优 |
| D，有可行候选才做 | 新 Native 确认与冻结的 farther 生成 | 先固定全部臂、scorer、样本及长度，不根据 32K 结果改 64K；Native 明确失败的候选不支付大规模远端确认成本 |

N_compact 若基本复现长输入效果，优先接受低成本解释；差异不显著不等于等价。若 N128 有额外的 far 内容收益，支持长输入适配增量，但仍未识别 FFN 必要性。若 Y 与 Z 相当或更好，收缩特定 Z 的方法创新主张。

单证据是新比较的主要生成 endpoint；绑定和 double 全量保留，报告未筛选结果与基线合格子集，不删除困难实例。资格不足限制相应机制主张。整体系统效果不要求 Native near 全会；纯距离机制应额外报告 Native compact 且 near 正确的固定子集，避免将背景失败归为距离。

**停止边界：** 共享有效性缺陷立即停止受影响实验；单任务族样本不足局部限制；完成固定配方后，候选 Native 任务或 PPL 保留低于 .88，或在已解析主生成任务上为零，关闭其后续确认。点值合格但 CI 不够窄是未解决，不自动加 steps。此次修订不把 R32 诊断当最终端点，也不把外部建议当无限运行授权。

**预算边界：** 新训练最多 N_compact、Z、Y 各一个 seed；沿用每臂 32R+96T 和现有资源保护，不扩步、不扫 rank/gain。启动前须记录既有引擎／配置／数据 hashes、实际空闲显存与磁盘、墙钟上限和异常退出。旧 N 的 28.7 分钟仅是历史测量，不能作为三臂时长保证。本次未启动这些运行。

## 4. 代码审阅：已有入口能做什么，仍缺什么

当前 [trainer](../../../../scripts/train/train_single_table_native_constrained.py) 已有 `--compact-only`：在资产验证后把每行 prompt 替换为已资格验证的 `native_compact_prompt_ids`，保留 `length_cap` 用于原三桶曝光顺序；`task_order` 和 `native_replay_order` 独立使用固定 seed。目标 IDs、CE／margin 与 Native 日程保持代码路径一致，无须重新设计训练器。

但这只是源码支持，不是已运行的 matched 对照。正式运行前须对照原 release008，核对 768 个有序目标／实例和 replay IDs；current trainer 后加了 prefix 及计数修正，不能仅凭同命令声称执行字节相同。最省事的方案是验证原冻结 release 是否已有该 flag，否则发布最小差异引擎并披露差异。

缺失的是本轮语义转换的冻结 rubric、臂隐藏清单及审阅输出；不能把 substring 脚本改名当语义审计。后续确认的新数据身份与逐子任务报告也须先固定。当前文档修订没有改 scorer、训练代码或旧 reviewer 的联合判决。

## 5. ROI 与两个问题的充分性

**零训练：没有充分解决方案。** 本审查提供了清晰止损与归因边界，没有提出已验证的新可行表。四个已测 OLMo 系统均未过联合标准，继续扫增益的优先级低。不能将“转入适配”称为解决零训练问题。

**轻适配：有高 ROI 的检验路线，尚无充分成功证据。** Native 表上已有严格生成改善和总体 Native 确认，最缺的是 compact 反事实与同模型 Z/Y 适配。三次有明确区别的问题比立即换 8B、增加 prefix 或消融 rank 更接近论文所需的闭环。成功概率目前无可校准数值，不虚报百分比。

本轮 Qwen 训练最长 16K、配置 Native 32K：即使 64K 成功，也只证明 4× 训练长度、2× 配置 Native 的对应结果，不能完成原目标中的物理 Native 2×/4× 训练及 8×/16×/32× 外推。那需要另立硬件可行且长度口径明确的后续协议。

若旧配方 Z/Y Native 仍失败，才优先比较真实 teacher 决策轨迹覆盖；若 Native 可行而内容学习不足，再登记 N/Z × prefix off/on 的固定增量。两者不同时改。FFN 暂保留为有用复合参数空间的一部分，attention-only r68 仅在联合工作点出现后用于贡献分析。

论文先回答表的增量、长输入训练的增量、独立 Native 代价三件事。2–3 个有互补作用的任务族可以形成有边界的实证，不宣称全面通用，也不以调窄问题掩盖 double 或格式退化。当前 TeX 不因这份计划自动升级结论。
