- **Purpose:** prepare the next frozen-checkpoint research cycle without

## 1. Outcome and non-goals

The next research outcome is one frozen-checkpoint allocation that improves
both Native-window and far-tail behaviour without training, routing, or an
attention-gain change. The first experiment is therefore a minimal matched
candidate screen, not another proof that allocation exists and not a mechanism
cube.

This preflight does not authorize inference, training, paid compute, server
access, or a manuscript claim. It does not select a candidate. Any GPU stage
requires a separate live readiness receipt and explicit author authorization.

## 2. ROI adjudication of the author-supplied v2.3 sprint

Every item was re-evaluated against five questions rather than inherited from
the supplied plan or its model reviews:

1. **Decision leverage:** which concrete candidate or claim decision changes?
2. **Non-duplication:** has a canonical owner or closed-route result already
   answered it?
3. **Identification:** can the proposed contrast estimate the stated quantity?
4. **Cost to verdict:** what CPU, engineering, GPU, and interpretation cost is
   paid before a stop decision is available?
5. **Reuse after failure:** does a negative result still close a branch or
   improve the next design?

An attractive theorem, more cells, a larger checkpoint, or an external-model
recommendation contributes no ROI by itself.

## 3. R1: freeze the candidate contract before model scoring

The candidate must state, before any evaluation output is read:

1. the exact source of its allocation signal;
2. how that signal uses checkpoint state or matched behaviour and therefore
   escapes the closed "shared one-dimensional table + static scalar score"
   class in `INDEX.md` §3.4;
3. whether it is task-label-free and target-length-free;
4. the realised float32 frequency tensor, pair count, endpoints, log-span, and
   hash;
5. the one decision it can change and the stop rule.

For the pure-$z$ screen, freeze and hold identical across arms:

- checkpoint and all weights;
- RoPE operator, pair count, sampled support, and attention gain;
- routing disabled for the complete request/KV-cache lifetime;
- token rows, row order, precision, attention backend, decoder, answer mask,
  and evaluation code.

Native, same-support geometric, derived, and coarse tables are completed
references. They are not candidates to rediscover, and official YaRN is not a
substitute for the same-support geometric control.

## 4. R2: minimal joint screen

### Primary gate

Use the same frozen row manifest for:

1. **Native-window likelihood:** full-sequence or registered answer-token NLL
   inside the checkpoint's Native window;
2. **far-tail likelihood:** the matched endpoint on positions beyond the
   Native window.

The candidate proceeds only if it passes both preregistered directions on the
same rows. A downstream score cannot rescue a failed likelihood gate. NLL,
exact match, token F1, and RULER remain separate endpoints.

### Required outputs

- per-row JSONL before aggregation;
- candidate/config/row/order hashes;
- Native and same-support controls under the identical execution contract;
- paired row contrasts and intervals with the fixed checkpoint/task-set scope;
- explicit pass, fail, or unresolved verdict against the frozen gate.

### Stop rules

Stop before GPU if the candidate changes support, gain, operator, routing, or
uses evaluation labels/target length contrary to its declared class. Stop on
backend fallback, non-finite loss, tensor/hash drift, missing per-row output, or
row/decoder mismatch. After a valid failed R2, do not tune on the failed rows.

## 5. Conditional diagnostics after R2

Position-binned NLL is the first analysis after a positive candidate because it
can reuse the same documents and distinguish local retention from far-tail
recovery. Use bins frozen before inspection and preserve per-token denominators.

The matched-content virtual-gap bridge enters only when all are true:

1. R2 is valid but mechanism-ambiguous;
2. content failure versus position/allocation failure would lead to different
   candidate designs;
3. the gap, gain cells, answer mask, sham parity, Native degradation control,
   and capability gate are frozen;
4. a dedicated runner passes CPU contract review and the author separately
   authorizes GPU execution.

The existing four-cell bridge remains the base protocol. A gain-expanded cube
is an extension, not a replacement, and must keep pure-$z$ and bundled-gain
estimands separate.

## 6. Code prepared in this sprint

`scripts/analysis/finite_k_cosh_regret_audit.py` evaluates the continuous Cosh
surrogate and its equal-mass quantile histogram exactly cell-by-cell. Its
default grid checks $K\in\{8,16,32,64,128\}$ and
$\tau\in\{0.5,1,2,4\}$, reporting:

- unscaled surrogate regret;
- $K^2$-scaled regret;
- the analytic coefficient
  $\frac{\alpha}{24}(\tau^2-\tau\tanh\tau)$;
- tail log--log slope and tolerance verdict.

The script's PASS status certifies only this numerical convention. It is not a
proof, an $r_2$ result, an LM result, or a candidate-ranking signal.
