## E. 审稿人点名的 OLMo 官方 YaRN 同 panel 基线 —— ★ **不需要写新代码**（我先前判断错了）

我原以为"实例上没有对应评测器，需新写一个"。**核实后是错的**：harness 是**表无关**的——
`runtime.install(model, table)` 接受任意表（`values_float32` / `gain` / `tensor_sha256`），
`run.py --prepared <dir>` 从 `<dir>/tables.json` 读具名表、从 `spec.json` 读方法队列。
**所以缺的只是一张表条目，不是评测器。**

**已完成（纯 CPU，零 GPU）**：
```
新目录 /root/autodl-tmp/olmo_fast_screen_20260908/prepared_natural_yarn_01
  tables.json : Native, MrPro, MrProBM, YaRN
    YaRN: gain=1.138629（与 MrPro/BM 匹配，同振幅对照）
          sum_m=42.9117, tensor_sha 由 harness 自己的 tensor_sha() 计算
  spec.json   : methods 增加 YaRN × 16（与 MrPro/MrProBM 同队列）
  其余文件（screen.jsonl/generation_config.json/manifest.json）与原目录逐字节相同
```

**约定守卫**：构造脚本在写入前先反推存储的 MrPro 表，要求
`j<=14 上 max|m|=4.97e-08`、`j>=32 上 max|m-1|=5.94e-08`、`sum_m=37.6667`
—— **37.6667 正是 `m_mrpro(n=18, low=14)` 的已知签名**，与 my m-坐标一致。
守卫第一次以 1e-9 容差拒绝（float32 存储），说明它确实在拒而不是在走过场。

工具脚本：`code/yarn_baseline/build_yarn_entry.py`、`code/yarn_baseline/add_yarn_spec.py`

```

  --prepared /root/autodl-tmp/olmo_fast_screen_20260908/prepared_natural_yarn_01 \
```
