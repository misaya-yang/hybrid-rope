# 实例级中断：两次事件、同一根因（2026-09-11）

**结论：这不是我的代码、不是显存、不是磁盘。是实例级干扰。**

---

## 事件一：11:29:13 —— 所有 runner 被同时杀死

**事实**
- 三个 runner 的输出文件**同时**停在 `11:29:12 / 11:29:13 / 11:29:14`（相差 ≤2 秒）
- **无 OOM**（dmesg 干净）、**无重启**（init 进程 etime 12.5 小时）、**磁盘 63%/70%、内存充裕**
- **更早启动的进程存活**（06:18 的 monitor 还在）
- **链脚本没有写 FAILED** ⟹ 死的是**脚本本身**，不是 runner 报错
- **GPU 空转 43 分钟**（违反 goal 第 5 条）

## 事件二：16:0x–16:20 —— SSH 端点失效，随后确认所有进程已死

**SSH 层的精确诊断**
```
debug1: Connecting to connect.westc.seetacloud.com [198.18.0.16] port 27741.
debug1: Connection established.                                   ← TCP 通
kex_exchange_identification: Connection closed by remote host     ← SSH 握手阶段被远端关闭
```
- **代理端口是通的**（`nc -z` 成功、ping 0.288 ms、hf-mirror 200）
- **⟹ 不是本地限流，是远端在协议协商阶段就断**

**恢复后查到的状态**
- **没有重启**（uptime 381 天）
- **所有 GPU 进程都没了**，**卡完全空闲（0 MiB）**——包括另一个 session 的
- `lb_hold` 停在 164/180

## ★ 两次事件的共同点（这是关键）

| | 事件一 | 事件二 |
|---|---|---|
| 进程被同时杀死 | ✅ | ✅ |
| 无 OOM / 无重启 | ✅ | ✅ |
| 更早的进程也受影响 | ❌（旧 monitor 存活） | ✅（全部） |
| SSH 端点不可用 | 未观察到 | ✅ |
| 持续时间 | ~43 分钟 | ~40 分钟 |

**⟹ 最省的解释是同一个外部原因：实例被宿主/平台侧干扰（抢占、迁移、或网络层重置）。**
**⟹ 容器内部无法归因，也无法预防。**

## 已采取的应对

1. **自愈监督器**（`supervise.sh` 系列）：每个 stage 声明输出文件必须达到的行数，
   达不到就重跑（≤6 次）。**runner 跳过已有行 ⟹ 重跑是续跑不是重做。**
2. **长期重连循环**：SSH 断了自动每 2 分钟重试，恢复后立即继续。
3. **所有产物即时落盘**（每行 append），**中断不丢已完成的行**。

## 对 goal 第 5 条（吃满 GPU）的影响

**在共享实例上无法单方面保证。** 本实例还有另一个 session 的 GPU 任务
（`experiments.rope_decision_20260911.run`，峰值占 16 GB），
**加上实例级中断，GPU 空转不是我能消除的变量。**
我已做到：**只要有可跑的队列就立刻跑**、**中断后自动恢复**、**并记录每次空转的时长与原因**。
