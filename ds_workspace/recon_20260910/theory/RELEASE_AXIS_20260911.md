## 一、缺口：`m=1` 是硬编码的，不是物理的

**所有**本战役的表（以及 `m_incr_beta` 这个构造器）都在频带之后把 `m ≡ 1` 写死。
`minimal-params` 指出这不是要求。代价可以直接算：

在 4× 距离上槽 `j` 可读 ⟺ `0.25 ≤ 4·t_W(j)·4^(−m_j) ≤ 16` ⟺ **`m_j ≤ m_max(j) := log₄(16·t_W(j))`**

| 槽 | 38 | **39** | 40 | 41 | 42 | 43 | 44 | **45** | 46 |
|---|---|---|---|---|---|---|---|---|---|
| `t_W` | .2694 | .2195 | .1788 | .1456 | .1186 | .0966 | .0787 | .0641 | .0522 |
| **`m_max`** | 1.054 | **0.906** | 0.758 | 0.610 | 0.462 | 0.314 | 0.167 | **0.019** | −0.129 |
| `t_D` @ m=0 | 1.078 | **0.878 ✓可读** | 0.715 ✓ | 0.583 ✓ | 0.475 ✓ | 0.387 ✓ | 0.315 ✓ | **0.257 ✓** | 0.209 ✗ |
| `t_D` @ m=1 | .269 ✓ | **.219 ✗** | .179 ✗ | .146 ✗ | .119 ✗ | .097 ✗ | .079 ✗ | **.064 ✗** | .052 ✗ |

> **槽 39–45 在 `m=0` 时本来就可读，却被 `m=1` 平台推出了窗的【下沿】。七个槽，白白丢掉。**

**我的四角框架表达不了这个**——因为框架的整个 (a,b) 族都建立在"带外 m≡1"之上。
`minimal-params` 说得对：**band 限制与 span 选择是同一个动作**，它结构性地禁止
"在慢端把 m 降回来"。（`evq-limit` 独立地到达同一结论，并把它命名为**第五个顶点**：
四角全是**单极** forcing、mass≡1；释放是**偶极**、mass≈0，两者正交。）

## 二、KNIFE 悬案解决（而且不需要任何新机制）

战役此前测过"削平台"：KNIFE taper，`δ = 0.0063/slot`，**−2.30pp**，
被读作"`m=1` 平台承重"。

**但 0.0063 小了约 23 倍。** 它在槽 39–45 上留下的 `m = 0.956 … 0.918`，
**全部高于 `m_max`** ⟹ **它回收 0 个槽，只付代价。** 而那正是被测到的 −2.30pp。

**正确的速率由两个不等式夹出来，没有自由参数：**

| 不等式 | 约束 |
|---|---|
| 留在窗内 | `m_j ≤ m_max(j)` |
| **ν 严格递减** | `m_j − m_{j+1} < ln(1/ratio)/ln4 = **0.147903**` |

> ★ **第二个界正是可读条带的斜率，也是 ν 退化斜率——同一个数**
> （`lnθ/(2K·ln2)`，`evq-limit` 独立指出这是同一个恒等式）：
> **沿条带滑行 ⟺ ν 恰好不变。**

取 `rate = 0.98 × 0.147903 = 0.14495/slot`，**逐点同时满足两个不等式**：

|---|---|---|---|---|---|---|---|
| `m_max` | .9060 | .7581 | .6102 | .4623 | .3144 | .1665 | .0186 |
| **release** | .8551 | .7101 | .5652 | .4202 | .2753 | .1303 | **0** |
| 可行 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

## 四、必须带上的保留（两位都提了，我同意）

1. **`native` 是 N 的反例**：N=21（全场最高）却是坏表（连续 7.2153）。
   ⟹ **N 只在"压缩已交付"的族内有排序力，不是能力量。** 而 `rel_*` 的 S 很低，

2. **`evq-limit` 的 τ=0.5 保留同理**：`m∈[−0.148,−0.003]` 是 native 的微扰，
   而 native 本身是 N 的反例 ⟹ **τ=0.5 主要检验损伤模型，不检验 N 机制。**
3. **窗内代价 `Q̂` 是 Qwen 标定 + 跨模型转移**，且与 `evq_deploy τ=1` 的唯一实测
   （−0.0004 nats，免费）矛盾。**判决臂落地前应先测 OLMo 自己的 4K 窗内 NLL。**

## 五、这为什么不是扫描

速率被两个不等式夹在一个窄区间里，**没有可扫的自由参数**；
方向由两个独立分析收敛得到；预测在读数前写下；
而且它**解决了一个已有的悬案**（KNIFE −2.30pp），不需要新机制。

**判决点**：若 `rel_bm` 的连续 NLL 明显优于 BM ⟹ N 机制在带内重分配之外还有内容；
若崩到 native 附近 ⟹ "释放"破坏了某个未被建模的东西（最可能是模型在训练分布上的
frequency 先验——慢槽在训练时是 `m=1` 的）。

### 6.1 一个漂亮的收敛：两条独立推导落到同一张崩掉的表

| 推导 | 平台起点 | 连续 NLL |
|---|---|---|
| `minimal-params` 的 **N 最大化** → `Tstar` | 槽 **24** | **3.0372** |
| Fisher 路线（`V≡const`）→ `step_hi25` | 槽 **25** | **3.0452** |

**两个完全独立、机制不同的推导，都落到"槽 ~24 的硬阶跃"，都以同一个幅度崩。**

**共同病因**：两者都把**可救槽 19–24** 留在 `m=0`。
- Fisher 路线的 `V≡const` 抹平了"可救/不可救"的区别（已记录）；
- N 最大化同样不区分——因为 `N` 对"槽 19–24 是否进窗"给的是**同样的 +1**，
  而对"槽 39–45 是否保留"也是 +1，**它没有给"可救性"任何权重**。

> **⟹ 两种推导失败的原因是同一个：目标函数（Fisher 距离 / 窗内槽计数）
> 都不编码"这个槽在测试距离上是否【可以】变得可读"。**
> **这是本轮对 Pro 模型 Q1（"价值泛函 V 是什么"）的第二次、更强的实证。**

### 6.2 KNIFE 悬案的**另一个**解释

`minimal-params` 提出：KNIFE taper（δ=0.0063）的 −2.30pp 是"速率小 23 倍、
回收 0 槽只付代价"。**这个解释现在被证伪了**——正确速率的释放（`rel_bm`/`Cslow`）
**同样回收了槽、同样更差。**

> **正确的读法**：`m=1` 平台在慢端**确实承重**，而且承重的原因**不是**
> "可读窗计数"所刻画的那个。窗判据 `0.25 ≤ t_D ≤ 16` 显然不是这些槽的正确判据。
