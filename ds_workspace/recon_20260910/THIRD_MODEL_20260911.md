## 三、★ 一个重要的额外信息：**1.5B 与 7B 同族、同 θ、同窗口**

```
Qwen2.5-1.5B：救援 +0.18
Qwen2.5-7B  ：救援 −0.05
```

**两者 θ=1e6、native W=32768 完全相同。差别是【模型规模】。**

> **⟹ "救援量"是一个【模型】属性，不是一个【RoPE 配置】属性。**
> **⟹ 这进一步支持答案：任何只由 `(θ, W, d, K, 带位置)` 决定的静态泛函，
> 在原理上就不可能预测最优端——因为救援量不由这些量决定。**
> **⟹ 这也解释了为什么 12 个静态泛函全部失败：不是没找到，是它们的信息不够。**

## 四、边界（必须写）

1. **Qwen 7B 的 NLL 是在 8192/16384/32768 上测的，全部 ≤ native 窗口（1×）。**
   所以那一组**不是外推测试**，是"窗内改表"。
   **⟹ 它说明的是"窗内改动就已经有害"，不能直接当作 4× 的救援量。**
2. **RULER 只有 18 行**（6@1× + 12@4×），@4× 的 −13.33pp 是 t=−1.43，**不显著**。
3. **三个模型的样本量、长度、评估协议不完全可比**（OLMo 是 350/180 行 RULER + 3 个 NLL 长度；
   Qwen 是 36/18 行 RULER + NLL）。**趋势一致，但不是同一实验的重复。**
