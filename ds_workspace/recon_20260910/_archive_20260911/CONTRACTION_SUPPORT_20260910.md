# 第二次解空间收缩：窗内轴**不**为三段式结构辩护

**日期**：2026-09-10 深夜
**触发**：support 轴前几臂 + 全部 round-1 臂的**逐长度** offset 校正
**结论**：**「保持区 m=0 是必需的」这条论证，在窗内轴上不成立。**

> ## ⚠ 本文的结论在第 5 节被**部分修正**——support 轴 14 臂跑完后，总跨度是 **3.17 nats**
> 而不是 0.003。写下本文时只看了一半的臂。**修正见 §5，请以 §5 为准。**

## 1. 先修仪器：offset 是**逐长度**的，不是一个常数

基线取自归档 `run_nll_01/MrPro.jsonl`（**逐行**前向），而这些臂是**分批**测的
（32 GB 卡在 batch=1 时基本闲置）。bf16 归约非批不变 ⇒ 每个 delta 带系统偏移。
`mrpro_n17` 就是 MrRoPE，所以**它的 delta 就是那个偏移**：

| 长度 | offset（nats） |
|---|---|
| 8192 | −0.000008 |
| 16384 | **+0.000350** |
| 32768 | **+0.000396** |

**跨三个长度差 50 倍。** 减一个平均值会让 32K 列残留大部分偏移、同时把 8K 列过度校正——
而 32K 列恰恰是**唯一能与归档对上的那一列**，弄错就把唯一能验证仪器的比较藏起来了。

**校正后，仪器在 32K 列上被验证：**

```
本 run：beta_b1(部署 BM) − mrpro_n17 = −0.001288 nats
归档  ：BM 2.08789  −  MrRoPE 2.08899 = −0.001100 nats
```

**两个独立测量在 0.0002 nats 内一致**，而待测效应是 0.001–0.002 量级。仪器可信。

## 2. 收缩的内容：整个「支撑」轴在窗内是平的

Round 1 的 29 臂**全部**把槽 0–23 钉在 m=0、槽 40 后钉在 m=1——它测的是**形状**，
从未测**支撑**。而 EVQ 的定义就是全局 companding（实测：`evq_deploy` 全家族
`held=0, plateau=0`，**动每一个槽**）。这个轴今晚第一次被跑。

**32K 列，逐长度 offset 已除：**

| 臂 | 组 | Σm | 32K 代价 |
|---|---|---|---|
| `back_r0` | 三段 | 31.556 | −0.002797 |
| `incr_r0` | 三段 | 32.000 | −0.002030 |
| **`beta_b1`（部署 BM）** | 三段 | 32.000 | **−0.001288** |
| `evq_deploy_t1` | **companding** | 29.575 | **≈ −0.0004** |
| … | | | |
| `incr_r4` | 三段 | 26.437 | 最贵端 |

**全部臂的 32K 跨度约 0.003 nats。**

两条推论，都是收缩：

1. **「保持区不可动」不是窗内代价论证出来的。** 一个**动每个槽**的全局 companding
   （`evq_deploy_t1`）在 32K 上并不比部署 BM 贵。若平台真的有代价，它应当在这里显形。
2. **粗糙度⇒损伤模型在部署对上失效。** `beta_b1` 的 `R(ε) = 0.00206` 是
   **所有三段表里最低的**（MrRoPE 0.0132），而它的窗内代价**高于** 27 个三段臂中的 25 个。
   这与 [KKT_ANALYTIC](KKT_ANALYTIC_20260910.md) §1.2 的**证明**一致：
   Dirichlet 能量**不是** Fisher 损伤型（`K_W` 只依赖 `max(i,j)`，`L_D` 不是）。

**⟹ 保持区留在 m=0，只能是**设计锚**（旋转算子与训练算子逐位恒等）或**一阶扭结**，
不能是「窗内代价」的边际论证。**而一阶扭结正是 EVQ_UNIFY §3 指出「缺的那次测量」：
m=0 处原生代价的一阶右导数 `n_j`。**

## 3. 与第一次收缩合起来看

```
形状轴：窗内 ≤5e−3 nats；长程梯度恒零          → 局部量描述不了
支撑轴：窗内 ≤3e−3 nats；全局 companding 不受罚  → 局部量同样描述不了
而端点实差：OLMo 48.5 点 / 0.83 nats
```

> **两个目标、两条轴，在任何局部测量下都是平的；而两个端点在全局上差 48 个点。**
> 这不是「还没找到对的局部量」，是**这条轴上没有可用的局部量**。

这条结论直接解释了 LESSONS L1 那 10 条同型失败：**问题看起来是局部的，行为不是。**
从今往后，该轴上任何候选若其唯一理由是某个局部量（梯度、粗糙度、Fisher、曲率），
**一律不进 GPU**。

## 5. 修正（support 轴 14 臂跑完后）

**本文 §2 的结论建立在只看了 companding 前 2 臂的基础上。** 14 臂跑完后：

```
全部臂在 32K 列的总跨度 = 3.171188 nats       （不是 0.003）
```

| 组 | n | 32K 代价 min → max |
|---|---|---|
| three-band | 27 | −0.000847 → +0.003775 |
| **leak** | 5 | **−0.006044** → +0.002634 |
| companding | 8 | −0.004840 → **+1.674819** |

**所以「窗内轴是平的」只对三段族成立。** 一旦离开三段族，窗内代价是巨大的——
`evq_shift_t2` 要 +3.17 nats，`power_p4` 要 +0.067。

**真正的规律按 Σm 排：**

| Σm | 臂 | 32K 代价 |
|---|---|---|
| 15.4 | evq_deploy_t4 | −0.0043 |
| 26–32 | 全部三段族 | ≈ 0 |
| 32.0 | beta_b1 / leak_a0 | −0.0013 |
| 34.3 | leak_a0p005 | −0.0038 |
| **36.6** | **leak_a0p01（最便宜）** | **−0.0060** |
| 41.2 | leak_a0p02 | +0.0026 |
| 44.2 | power_p2 | **+0.0406** |
| 47.0 | power_p4 | **+0.0668** |

> **窗内代价在 `Σm ≲ 37` 上是平的（甚至略负），超过 ~41 后急剧上升。**

**这修正了两件事**：

1. **保持区并非完全不可动。** `leak_a0p01`——把压缩渗进保持区直到 `m[23]=0.23`——是
   **所有臂里窗内最便宜的**（比 MrRoPE 还好 0.006 nats）。所以「保持区有窗内代价」
   在 m[23] ≤ 0.23 的范围内**是错的**。
2. **但平台上界是真的存在**，只是位置比我原先说的远：转折在 Σm ≈ 38–41，
   不是 0。`leak_a0p02`（m[23]=0.46）开始付费，`power_p2/p4` 付费很多。

**因此新的判决实验（已排队 chain_v6b）**：`leak_a0p005 / a0p01 / a0p02` 在 **OLMo 16K
长程**上跑。若泄漏在长程**有增益且窗内免费** ⇒ 三段式确实**过度约束**，EVQ 的
全局支撑合法；若无增益且窗内可见代价 ⇒ `m=0` 处有一阶扭结，两个问题不同。
**两条分支都是结果。**

**同时记一个我自己的错**：本文 §2 表格里写 `evq_deploy_t1 ≈ −0.0004` 并据此下结论，
是在 14 臂里只看了 2 臂。**半程数据下结论**——这本身就该进 LESSONS。
