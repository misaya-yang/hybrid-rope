# 零训练筛选：第一小时规程

目标：**为 KKT 理论取数**——YaRN 家族到底凭什么强、EVQ 能不能同样强、以及
MrRoPE 是不是这条 `min L_long s.t. D_N ≤ eps` 上的驻点。本屏幕是**测量仪器**，
不是打榜：它沿两条理论上可分离的轴取点，看价格是否平衡。

本文件只管第一小时；它不训练、不写检查点、不改权重。

## 0. 为什么这条路线能一小时跑 10 个以上的方法

旧的链（`curvature_20260910` 的 s2a/s2b）用**中心差分**求长程梯度：36–60 次
128K 前向、20–34 分钟，只为一个梯度。筛选不需要梯度，只需要**每张表一个分数**，
而分数是"每篇文档一次前向"，且基准前向（native 表）所有臂共用一次。

成本 = `n_arms × n_docs × per_forward`，`per_forward` 由长度决定。归档值（32K
4.1 s、64K 16.0 s、128K 33.9 s）是**投影而非本包实测**，所以驱动会先跑第一个臂、
打印实测 per-forward，再决定是否继续。

## 1. 长度：唯一必须现在定死的选择

被评分的尾部位置必须**超出原生窗口**（32768），否则 `long_nll` 就变成一个窗内数字，
而窗内正是这些表**不该改变**的东西。文档长度决定两件事：

| 文档长度 | 外推倍数 | 实测 per-forward | 8 篇/臂 | **臂/小时** | 判决力 |
|---|---|---|---|---|---|
| 65536 | 2× | ~16 s（投影） | ~128 s | **~28** | 2× 外推 |
| 131072 | 4× | ~33.9 s（投影） | ~271 s | **~13** | 4× 外推，对准 panel 的关键长度 |

两者都过"一小时 10 个方法"的门。**建议先用 64K 跑全库（28 臂/小时），把幸存者
再用 128K 复跑**——这是唯一一个"先粗后细"而不构成隐藏扫描的安排，因为两个长度
的判据在跑之前就已经写在这里了。

**语料在服务器上（codex 做实验用的就是那批），开机第一件事是确认哪一份够长。**

唯一要注意的算术：被评分的文档必须超过 `窗口 + keep`。若服务器上那批是 32769 tok，
窗口 32768、keep 512 会被驱动直接拒绝（32769 < 33280），此时用
`make_corpus --concat 2` 把两行拼成 65538 tok 即可——**不重新分词、不新增数据**。
这只是个算术校验，不是要找新语料。

## 2. 开机后的顺序

```bash
# 线路 1：代数门（免费，无卡）
python -m experiments.zerotrain_20260910.selftest
python -m experiments.zerotrain_20260910.selftest --bank    # 打印候选库与预注册判词

# 线路 2：屏幕（需要卡；先 8 篇 64K）
python -m experiments.zerotrain_20260910.run_screen \
    --model  $MODEL \
    --corpus $CORPUS_64K \
    --keep 512 --limit 8 --out runs/screen_64k_01
```

驱动会按顺序做四件事，每一步失败都不进入下一步：

1. **代数门**。`incr_r1` 与 `mrpro_n17` 必须逐位相同，否则整张排行榜是"自信的废话"。
2. **语料检查**。文档必须是 `window + keep` 以上；不满足直接拒绝，不截断。
3. **先跑一个臂，再决定**。打印实测 per-forward 与剩余预算，然后才提交其余的臂。
4. **按声明顺序跑完**。**不按分数提前停**——因为输就砍臂正是项目禁止的多候选扫描。
   只按时间预算或 `runs/.../STOP` 文件停，未跑到的臂记为 `not_run` 并写进回执。

## 3. 候选库（预先声明，共 30 个臂）

`--bank` 会打印全部。四个组：

- **reference / incumbent**：`native`、`yarn_lin`、`mrpro_n17`、`mrpro_n16`
  （R1 查明 **Qwen 上的 YaRN 分数列在归档里是空的**，所以这一行无论结果如何都是新信息）
- **project**：`evq_deploy_t1p414`
- **mechanism**（核心）：`front_a{0.001,0.03,0.10}` / `back_r{0,2,4}` / `both_a{0.03,0.001}_r2`
- **shape_family**：`incr_r{0, 0.5, 1, 1.5, 2, 3, 4}`（单参数对照，与机制族共用锚点）
- **splice**：`splitA_s{24,28,32,36,40}` / `splitB_s{24,28,32,36,40}`

### 这个屏幕测的是理论，不是排名

KKT 说的是：在 `min L_long s.t. D_N ≤ eps` 下，**沿每条可移动的轴，价格应当平衡**。
所以三条读数直接就是三个理论判决：

| 轴 | 读法 |
|---|---|
| **前缘扰动** `a`（首增量占比） | `a` 平 ⟹ 前缘保护这一项在 MrRoPE 处已平衡；不平 ⟹ MrRoPE 不是该轴上的 KKT 点，且斜率符号指出该往哪边挪 |
| **后段集中** `r`（尾部指数） | 同上，针对 η 承担的尺度扩展这一项 |
| **EVQ 的位置** | EVQ 是同一平面上的一点还是一个平面外的点；它在价格结构里的位置是否与它的 companding 规则一致 |

**为什么必须双参数。** 单参数族 `ε_q ∝ q^r` 把两个机制**一起**动：提高 r 同时减小前缘扰动、又把压缩推后。沿它得到的分差**无法归给任何一个机制**——而"YaRN 家族凭什么强"问的正是这件事。所以核心族改成两个独立的旋钮：

    eps_1 = a              （前缘：1 - S^{-a}）
    eps_q ∝ q^r  (q >= 2)  （后段：eta_q 的形状）
    归一化 => 跨度恒为 1

**(a, r) = (2/306, 1) 就是 MrRoPE**（精确算术下逐位相同；float64 下差 1 ULP——多了一次归一化，自测里记录该 ULP 数而不是假装相等）。所以原点是被挑战者本身，两条轴读作"前缘扰动得更少/更多"与"后段压缩得更集中/更散"——正是当前理论那两句话的形式。

自测钉死了独立性：变 `a` **不动尾部形状**，变 `r` **不动首增量**。若任一泄漏，这个族就退化成它要取代的单参数族。

### 单参数 r 族仍然保留（作为对照与锚点）

`incr_r{0,0.5,1,1.5,2,3,4}`。其中 `incr_r1` 与 `mrpro_n17` **逐位相同**（`np.array_equal` 为真），是回执里的免费一致性检查：两者若评分不同，问题在驱动而不在物理。

### splice 组是 K6 的修正版

规划里字面写的 `max/min` 构造**是退化的**：它与 MrRoPE 只在槽 38、39 上不同
（两条 m 曲线在 37/38 交叉，逐槽取较大频率几乎恒选 MrPro），所以它测的是最后两个槽，
不是"前段保护 vs 后段压缩"。`splitA/B_s*` 才是"前段取一边、后段取另一边"，
s=24 与 s=40 恰好是两张原表，中间才是真正的测试。详见
`analysis/route_read_20260910/K6_PREFLIGHT_20260910.md`。

## 4. 结果怎么读

每个臂给**两个数**，构成 (price, benefit) 平面上的一点：

- `native_kl` = `E_u[KL(p_native || p_table)]` —— 代价（规划的约束侧）
- `long_nll` = 超窗位置的 NLL —— 收益（规划的目标侧）

判决不选"最小 NLL"，而看**谁在相同 native_kl 下 long_nll 更低**。被 MrRoPE 支配的臂
是一个结果，不被支配的也是。

**这个屏幕不能宣称什么**（回执里逐条写着）：`long_nll` 是留出文档上的语言建模数字，
**不是任务分**。一张表可以靠让模型对普通续写更自信而压低它、同时把每个 needle 都答错。
屏幕排序的是**臂**，不证明赢家在任何用户关心的能力上更强。把幸存者交给任务 panel
是另一个、已排队的步骤。

## 5. 已知的坑（都已写进代码，勿绕过）

| 坑 | 处置 |
|---|---|
| 表非单调 ⇒ 槽位静默重排 | 守卫在 **ν 严格递减**上，**不在 m 上**——规划明文禁止强制 m 单调（"会排除 EVQ 中的加速或非单调搬运"） |
| 文档不够长 ⇒ 窗内指标 | 拒绝并说明，不截断；服务器上若只有 32769 行，用 `--concat 2` |
| 基准前向重复计算 | `warmup()` 一次，所有臂共用；`score()` 在未 warmup 时抛错 |
| 位数比对 | `incr_r1` vs `mrpro_n17` 必须在回执里 `identical_tables: true` |
| 长 nll 与 native nll 符号 | `long_nll_gain = native_nll − long_nll`，**正数为更好**，自测里钉死 |
